# 实施方案

采用学生后端内统一 learning_records 模块，新增草稿与提交快照两张表。相比扩展仅能存文本的预留作业表，这能同时表达多题、课堂输入、测验和作品凭据；既有表与历史保留。用户身份只从 require_login 获取。

草稿按 user/course/module/activity/kind/content-version 唯一；乐观版本控制避免旧内容覆盖；提交使用客户端请求 ID 幂等，并在同一事务保存草稿、不可变快照与兼容练习历史。答案和客户端练习反馈标明来源，正式评分保持未评阅。

新增鉴权读取、保存、提交、历史 API，限制体积及字段。前端共用状态保存 hook，使用明确捕获的账号凭证、身份命名的本机缓存、串行防抖请求及冲突提示。账号切换立即隔离视图，不自动迁移匿名旧数据。

现有驾驶规则页面和旧答题组件接入；考试持久化能力经 API 实测。保持未登录体验可用，本机存储清楚标示；正式页面失败不虚报已提交。不改课程内容或制造 AI 评分。

先跑临时数据库 API/并发/隔离测试，再启动本地服务应用新增表，浏览器验证跨会话恢复。保护已有未提交改动，仅暂存本轮差异，commit 后立即 push。
