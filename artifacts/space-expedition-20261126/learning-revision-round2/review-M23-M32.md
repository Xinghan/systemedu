# M23–M32 独立科学与教学完整性审查（第二轮）

审查对象：`systemeduidea/projects_data/lightkurve-transit-detective` 当前 M23–M32 的 lesson.md、assignment.md、theories.json，以及 `practice/analyze.py`、17 格 `kepler10-reproduction.ipynb`、README/START-HERE、manifest、已有教师运行结果和学生 ZIP 文件清单。面向没有天文、统计、编程基础的初中生。课程源码只读；本报告不是试教结果，不表示学生已经能够独立完成。

本轮新增解释已经使“为什么要这样做”比原先明确，构造例与真实数据、复现与首次检验等边界也较清楚。但这些解释尚未与可逐节执行的程序、真实文件和学生判断连成完整路线。尤其是 M24、M26、M28、M31，照着现有文件操作仍不能完成作业规定的核心产物。继续补段落不能替代这些缺口。

## 最严重的五项

1. **预测表、覆盖表与比较图没有生产步骤。** M24 要 CSV/预测图/边界表，程序只写预测 JSON，Notebook 只打印前三行。M26 要逐窗 coverage_status/reason，程序只计窗内点数；不能把点数当作“充分观测”，更不能自动当作“支持预测”。
2. **M23 的封存入口会重新执行整套搜索。** `develop()` 重做粗搜、保护后的细搜，再生成新的 eph。学生前面逐节得到的候选与此入口之间没有核对和交接。M28 又要求固定已保存方法复现，但程序没有对应入口，新目录 `validate` 缺配置，`develop` 会再搜索。
3. **M31 的单变量实验与现有程序不一致。** 正文要求保持候选事件排除规则；内置 `window_sensitivity_days_unmasked` 明确不排除事件。直接改 CONFIG 后 develop 又会改动搜索结果，无法把变化只归因于窗口。
4. **持续保存、重新打开和真实执行的路线不完整。** Notebook 首格使用临时目录，重跑首格就换目录；学生未获教授如何继续上次分析。M29–M30 要安装日志、依赖、容差表、比较结果，但没有相应生成单元。学生能读懂“保存”仍不知道文件在哪里、用哪个环境执行。
5. **结论和总交付依赖尚未建立的证据链。** M27 要从 M26 引用覆盖数量，但 M26 不产出分类；M32 要全部前置材料和最终新运行，没有明确拷贝/相对链接映射及缺项反馈。`reference-results.json` 中有程序固定的参考 conclusion，不能拿它自动填成学生本人的判断。

## 逐节问题、材料与验收点

### M23 在检验 Q4 前记录分析方法和参数

**问题 1：前面得到的候选没有真正交接到封存。** assignment 的 develop 命令调用 `analyze.py:254–305`，重新搜索周期；正文却说“把已经选好的方法带过去”“从配置读回参数”。CLI 只有 stage/output，无外部配置参数（370 行）。这不是单纯缺少注释，而是动作与学习目标不同。

修法：新的分节 Notebook 直接接收 M22 的 `bundle/lc/eph/flat/trend`；核对原输入、候选、保护规则及实际窗口，再生成兼容 validate 的 freeze 和 development-results。可以按同一固定 eph 重新算趋势做一致核对，不能再搜索周期。材料：已填写一行的“字段—它控制什么—来自哪一节—单位”表，学生补其余项。检查：从 JSON 读回的三个历表参数与 M22 实际对象相等，Q3 处理数组一致，Q4 亮度尚未读取。

**问题 2：要求学生预先规定充分覆盖和判断标准，却没有教规则的适用范围。** CONFIG 的 5、5、0.5 是课程固定描述性检查；原程序没有逐事件可测性的规则。不能让初中生随手发明一个点数门槛，再把它当科学充分性。

修法：分开讲“时间上有几个点、是否跨越全窗”和“信号是否足够精确可以评价”。前者可定义并自动记录操作规则；后者不由点数直接判定。先演示三行构造数据，比较缺测、有采样但噪声大、整体叠加可见。`predeclared-rules.md` 提供对应真实字段的模板，学生写出自己准备比较什么及不能推断什么；三个统计阈值明确为提供的课程规则，不表示确认概率。

### M24 在查看 Q4 亮度前预测下降时间

**问题 1：四项作业只存在名称，Notebook 没有生成动作。** `develop:293–298` 只写 JSON，Notebook 对 windows 只显示前三行；无 CSV、预测图、边界表程序。

修法：按“读取 freeze→读取 manifest 头信息→逐个编号算中心/起止→导出所有行→只画覆盖范围和预测”拆格。教 `rows.append` 保存一行、CSV 表头与键一一对应；显示首/中/末三行供学生手算。边界表单独枚举与覆盖相交但中心不在内的事件，不改主预测。检查：事件编号唯一，中心差等于 P，CSV/JSON 全量一致，图不包含 Q4 亮度。

**问题 2：手算教学与正式精度没有操作隔离。** 正文虽要求保留完整精度，但没有告诉学生如何从实际 JSON 取得数字，容易手抄屏幕短小数。

修法：计算单元始终使用 `freeze['ephemeris']`，只在显示标签格式化。calculation.md 留首/中/末行的代入式与个人解释栏；教学数据单列，不能把 t0=100/P=2 写入真正配置。进阶方差公式已经标为非前提，主线不强迫零基础学生计算尚未估计的计时置信区间。

### M25 按已记录的方法处理 Q4 观测

**问题 1：进入 Q4 的操作门与完整先后检查不足。** README 说不要提前运行，Notebook 可从首格一键跑到 validate；前置记录未与实际访问动作联动。

修法：明确 `Q4_REVEAL=False` 为等待学生决策的闸门；先打印封存和预测的路径/hash、此前接触情况，再由学生改成 True。未开启时 M26–27 显示待完成，不产生假结果。说明此门不能证明学生未在外部看过公开资料；exposure 由学生填写，程序不替他声明盲测。

**问题 2：应比较的叠图没有产生。** `curve_plot:235–251` 画归一化/趋势、时间光变、折叠图，没有叠加原预测窗。assignment 要记录“有覆盖且下降/未下降”等，但程序没有逐事件信号估计。

修法：新增固定预测窗叠加时间图和逐窗局部图，写明看的是时间位置、采样和噪声；先描述可见事实，再留学生判断栏，不自动逐窗宣布检出。捕获实际 stdout/stderr 为 run.log，错误也保存；首次 JSON 保留，重复阅读不改写首次历史。

### M26 比较预测与 Q4 观测的差异

**问题 1：字段和承诺不对应。** assignment 要 `predicted_centre_bkjd/inside_count/coverage_status/reason`；真实结果只有 `centre_bkjd/accepted_observations_inside`（329–332 行），后两个字段完全未计算。validate 以筛后时间重枚举事件，而不是从事先预测左连接。

核对当前教师参考：主预测和首次结果都是 cycle 110–134 共 25 行，没有实际漏行，也没有窗内点数为 0 的事件。这里不能夸称“当前已经丢了边缘事件”；问题是方法没有保证原表完备，以及学生缺少逐窗采样证据。

修法：以 M24 `windows` 为唯一主表，逐个计算窗内数量、两侧采样、最大采样间隔、原始/保留点数和缺测原因。自动标签只能描述时间覆盖；“支持/不支持/信号精度不足”由实际测量能力另行判断。检查：输出 cycle 列与预测逐项相等；零点数保留行；从任意一行能打开对应局部图。

**问题 2：整体统计缺字段位置和算例到真实值的过渡。** 真实 depth、经验标准误、z 和 timing 分散在不同 JSON；正文解释了 ppm 和单位，但没有“打开哪份、取哪个字段、相减顺序”的单元。

修法：表列 Q3/首次 Q4 的 `fixed_box_depth.depth_ppm` 等字段与来源路径，直接计算 Q4−Q3，逐步显示绝对差/合成尺度/比值；同时显示限制。时间移位单列，不能当逐事件中心。不要用 `all_predeclared_checks_pass` 推导每个事件成功。

### M27 写出与证据相符的检验结论

**问题 1：结论任务要求的分组在前一节没有被测出来。** 正文 39 行要求“覆盖充分、部分覆盖及缺测数量”，但本包既未计算逐事件信号可测性，也未拟合事件中心。构造例假设“下降能清楚区分”，真实数据不能直接套用。

修法：结论分为可自动核对的事实、学生解释、未完成检查三栏。事实索引可自动写路径/hash/字段名；判断栏保持待填写。用一条实际来源做示范索引，但不自动写科研结论。提供反例：全窗有三点，但单点散布远大于预期下降时，不能凭三点就宣布逐事件通过。

**问题 2：完成反馈只检查能否找到文件，未检查断言力度。** M27 theories 为空，练习和正文主要是一般性用词纠正；应增加针对本人材料的核对动作。

修法：让学生标出结论中的每个数量、对象和动词，逐项连到来源；缺出处或超过计算范围时反馈具体缺项。若没有独立复核者，状态写自查/待复核；自动生成文件不等于学生解释已完成。特别禁止把 `analyze.py:355` 的固定 reference conclusion 作为学生答案。

### M28 整理可以从头运行的分析程序

**问题 1：按冻结参数复现缺入口。** 新目录 validate 会因没有 freeze 报错（312 行），即使仅复制 freeze，最后仍需 development-results（350 行）；develop 会再搜索。正文 57/85 行要求不重新搜索，现有 Notebook 路线未满足。

修法：提供独立 `replay_frozen.py`，明确读实践包代码、原 run 的 freeze/预测/首次结果；校验源码与 config 后，使用固定 eph 重新 read_role/local_median/measure，输出另一目录。记录这是已查看数据上的重复计算。它不生成“新的首次检验”，不覆盖原件，不调用 search/develop。给出完整命令和输入/输出表，运行日志由 subprocess 实际产生。

**问题 2：首次 Notebook 目录不持久。** 首代码格调用 tempfile.mkdtemp；重启并重跑首格会创建另一目录，屏幕上一串路径是唯一线索。

修法：新教学版明确使用 `practice/student-runs/<run-id>`，首格显示路径、恢复上次 run 的方式和关键文件状态；学生知道“打开同一 Notebook”不等于“恢复同一 run”。本节依赖表由代码能验证的路径生成初稿，学生解释各步作用。检查新进程执行，不以当前内核成功冒充重启验证。

### M29 写清软件环境、数据来源和运行方法

**问题 1：要求保存实际环境和安装日志，但没有操作单元。** README 已提供 macOS 验证环境与 venv 安装命令，然而 assignment 的 environment.txt、data-manifest.csv、install.log 没有从真实环境导出的方法。学生不能从 requirements 推断本次 kernel 的版本。

修法：使用 `sys.executable/platform/importlib.metadata` 记录当前环境，用 `sys.executable -m pip freeze/check` 捕获真实输出；manifest 逐文件核对大小/hash并导出 CSV。安装新环境另列命令和实际执行选项，未安装时标待验证，不用当前 pip check 冒充新环境安装成功。说明代码格与终端命令分别在哪里运行。

**问题 2：电脑/Notebook 与 iPad 学习状态没有可恢复交接。** 正文正确承认 App 未自动运行，但仍缺学生将实践包、run 和回答带回项目的位置说明。

修法：交付中区分课堂记录、下载包、运行目录；把“环境安装未验证、程序未运行、回答待填写”分别保留。若本轮不接 Python 后端，就不能宣称 iPad 内完整闭环已实现；可以提供明确配套环境路线，但必须实测该入口和文件导出路径。

### M30 请他人按说明重新运行并核对结果

**问题 1：容差知识不等于能执行对比。** expected-rules.csv、comparison.csv 无程序；给的 2 天教学容差不能直接当真实测量精度。哪些字段精准比较、哪些允许浮点差异也没有具体表。

修法：先写规则文件，再独立运行 M28 脚本。输入/代码/hash、保留 CADENCENO、预测 cycle 精确比较；固定规则的深度等采用明确标作“重算数值容差”的预置课程规则，并说明不代表天文误差。比较时输出 expected/actual/difference/rule/status，遇不同首先指向第一处分歧。规则 hash 写进日志，禁止事后放宽隐藏失败。

**问题 2：自动自检容易被写成他人独立复查。** “请同伴”不能由一次本机 subprocess 自动兑现。

修法：runner.md 由人填写身份与实际环境；机器结果写“本机新进程数值复算”。未有另一人记录就保留待同伴核验，不能填姓名、安装成功或已独立验证。失败日志和 issues 均保留。

### M31 改变一个参数，解释结果为什么变化

**问题 1：原内置敏感性不是本课要求的保护式单变量试验。** `analyze.py:272–283` 调 `flatten(clean,None,window=w)`；lesson 要保持候选事件排除规则一致。直接改 CONFIG 再 develop 还会重新搜索 eph。

修法：先读取未改动的原 freeze，固定同一个 eph、相同 Q3 retained CADENCENO、质量/归一化/分段/最少支持点；仅调用 `local_median(lc,eph,window_day=W)` 改窗口。使用同一 eph 测深度；不搜索、不使用 Q4 调参。存输入行号相同检查、两条趋势、支持点数、固定盒深度、错误。不能预设窗口窄一定变浅。

**问题 2：预测、失败保留和恢复原方案没有执行材料。** 作业列五文件和 restore，却未给在哪改单个数、如何记录失败和从新进程恢复。

修法：参数格只有 WINDOW_TRIAL，先填写本人预期，再生成 attempt 编号保存每次结果；ValueError 也写结果与原因。最后核对 freeze/source hash 并运行 M28 固定方案脚本到 restore 新目录，比较数值。预测栏不由机器根据最终结果反填。

### M32 提交完整的凌星分析项目

**问题 1：文件体系未贯通。** 原程序只写 audit/browser；作业从 M23 起另要求多套 Mxx 目录，最终又换 inputs/frozen 等分类。没有映射工具，学生只能自行猜复制哪些文件。

修法：总索引列“课程步骤→真实相对路径→来源→是否存在→是否待学生完成”，保留原 run 不搬走文件。归档时保存清单/hash并验证所有相对链接。缺失项明确报告，不造空文件显示齐全。历史首次、重算、参数试验分开。

**问题 2：完成不能由文件存在代替理解/评审。** 本文已经正确提出四种检查，但仍无对应分开的状态。

修法：提供自动“材料/运行检查”，人工“解释/证据判断核验”两组状态；未填结论和未有同伴记录保持待完成。让学生从本人图任选一点说明时间、量、单位和原始行号，再解释一个可能推翻当前解释的检查；检查者记录实际提问和回答。不能由读完最后一页自动宣称课程目标达成。

## 范围与验证说明

- 所谓“不生成”是指核读到的当前程序和 17 格 Notebook 没有该文件的写出路径；允许手工作品不等于问题已解决，正文还需要教会怎样建立、检查、保存这些作品。
- 核对了现有教师 audit 的实际 schema 和 25 个预测编号；没有把教师运行当学生运行，没有执行学生新分析，也未修改 canonical 课程。
- 现有学生 ZIP 不含教师 audit，符合不把答案作为学生结果的边界；但 README 提及 `execute_notebook.py`/`verify_package.py` 的已执行检查，这两个脚本并未列入下载 ZIP。若要求学生照该命令检查，应把工具纳入包，或明确这些是教师验收命令。
- 配套 `draft-M23-M32.json` 将提供教学版单元草稿。其正确性仍需整合 M01–M22 的实际变量契约后空内核执行、关闭/开启 Q4 门分别验收及人工读图，不能仅凭 Python 语法通过宣称教学闭环已完成。
