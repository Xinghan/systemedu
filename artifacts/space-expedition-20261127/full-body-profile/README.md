# iPad 全身卡通队员档案 · 2026-11-27

用户已取消需要外部模型服务的动态全身 3D，当前交付为基于照片或已有卡通头像重绘的静态全身立绘。

## 行为

- 点项目顶部头像或首页队员卡打开原生全屏档案：完整立绘、角色职责、任务和署名作品数量。
- 上传照片后生成全身人物；已有卡通头像也可通过「设计我的全身形象 → 用当前形象生成全身立绘」升级，不必重新提供原照片。
- 图像要求单人、头顶到鞋底全部入画，沿用脸型、发型、年龄感，补全科研制服。完整图保存在既有 profile document，另外裁出脸部缩略图供导航与课堂使用。
- 生成结果先预览，点保存才更新身份。返回或生成失败不覆盖已保存的档案。旧头像、旧作品快照和学习记录保持可读。
- 新增测试图仅在 UI test bundle 中，用合成角色测试，不含学生照片；测试数据仅写入 UUID 隔离数据库。

## 验证

- Debug 构建通过，安装到 iPad Air 11-inch (M4)，UDID 514BC1A2-E3D6-47CE-B4C6-823459A82BEB。
- Python 服务测试 11 项通过，含图像比例/去元数据、ready 合约、去重/删除，以及既有相机服务检查。
- Swift 单元测试 4 项通过：旧档案解码、脸部裁切与课堂传递、保存/重新读取档案不重置学习记录、既有图片桥接兼容。
- 额外开启真实服务集成测试 1 项通过：从模拟器内调用 `AvatarService.generate`，实际 POST、轮询全身结果并删除临时作业；验证返回竖幅图且最长边不超过 1024。测试使用内置合成角色。
- UI 测试 2 项通过：横竖屏完整立绘、编辑取消/重开保持身份；旧半身头像进入升级页且取消不覆盖。
- 直接调用真实图片供应商，使用仓库内置工程师卡通图作为输入，返回 683×1024 JPEG；人工检查头发、双手、双腿、两只鞋均完整显示。
- 首轮 UI 测试暴露父容器标识覆盖子控件的问题；去除父级标识、区分首页和档案立绘标识后重测通过。截图为最终通过的测试结果。

## 使用边界

图片生成仍是已有 Debug + Simulator 的本机预览服务，使用既有通义配置，监听 127.0.0.1:8769；未部署真机/生产服务。无 Meshy、3D 模型或动画能力。当前用户头像没有自动迁移，需在档案里触发升级并确认；桌面自动点击接口在此次验收中报 windowNotFoundAtPosition，未通过直接修改用户数据库绕过。
