# 项目级模拟游戏设计 Prompt — purpleair-airquality-node

> 用途: 项目级(而非 knode 级)交互模拟游戏。一个项目一个 HTML,整体模拟该项目的**最终产出物**,
> 让学生在开始学习前就"玩到"自己 26 周后将做出的东西。
> 本文件是给实现者(Claude Code)的完整设计规格,实现时严格遵循。

## 0. 项目背景(来自 blueprint)

- 项目: 接入 PurpleAir / OpenAQ 的空气质量节点(运行 EPA NowCast), 10-12 岁, 26 周
- 最终产出物: 一个**经过校准、在 PurpleAir + OpenAQ 公开地图上可见的实体传感器节点**,
  附 30 天数据集(Zenodo DOI)、EPA 校正、NowCast AQI、与最近 EPA AirNow 官方站点的交叉验证报告、公开实时仪表盘。
- 硬件: Pi Zero 2 W + PMS5003(激光 PM 传感器, UART) + 备份 PMS7003 + BME280(温湿压, I2C) + MQ-135 + 带通风防水盒 + 视线高度安装。

## 1. 游戏定位与核心幻想

**名称**: 我的空气质量节点 / My Air Quality Node
**核心幻想**: 你是社区空气质量网络的一名新晋节点运营者。从一堆零件开始,搭建、部署、运行、校准
一个真实的 PM2.5 监测节点,熬过烟雾日和阴雨天,证明你的数据靠得住,最终让你的传感器点亮在
全球公开地图上。

**设计原则**:
1. 模拟的是**产出物**,不是课程知识点 —— 玩家操作的对象就是那台节点本身和它产出的数据。
2. 所有数值必须**真算**: EPA 校正公式、NowCast 加权平均、AQI 分段换算、相关系数 r、MAE
   全部用真实公式在 JS 里逐时计算,不做假动画。
3. 玩家的**每个工程决策都留下后果**: 接错线 → 数据乱码; 密封盒 → 读数迟钝; 装在烧烤炉边 →
   系统性偏高; 不做湿度校正 → 阴雨天虚高、验证不过关。后果在第 3/4 章以数据形式显形,
   并允许回头修复(镜像真实项目 W18-19 的"诊断偏差 → 改进校正"循环)。
4. 失败不是终局而是诊断入口: 验证不达标时给出可交互的诊断线索,修复后重新验证。

## 2. 章节结构(镜像项目 4 个 Phase)

单页四章连续推进,侧栏 roadmap 显示进度。全程一个存档状态对象 `S`,前章决策影响后章数据。

### 第 1 章 BUILD — 工作台搭建
- 场景: 左侧零件架(Pi Zero / PMS5003 / PMS7003 / BME280 / MQ-135 / 三种外壳),右侧主板特写。
- 交互 A — 接线: 点击零件上机 → 出现接线小谜题。PMS5003 是 UART: 玩家要把传感器 TX 连到
  Pi 的 RX、RX 连 TX(交叉)。连直连(TX-TX)会通电但数据乱码 —— 不当场报错,允许带病进入第 2 章,
  乱码会在第 3 章开机时显形(还原真实调试体验),提供"回工作台检查接线"按钮。
  BME280 是 I2C: SDA-SDA / SCL-SCL 直连即可,与 UART 形成"为什么这次不用交叉?"的认知对比(guide 里点破)。
- 交互 B — 外壳三选一: 全密封防水盒(防水 100 分/气流 0 分)、开放网罩(气流好/进雨)、
  带挡板通风防水盒(正确)。选错可以继续,后果: 密封盒 → 第 3 章读数变化迟钝且偏低; 网罩 → 雨天数据缺口。
- 通过条件: 至少装上 PMS5003 + BME280 + 任一外壳即可点"通电测试"进入下一章(备份传感器与 MQ-135 可选,装了在第 3 章多一条对照曲线/交叉冗余提示)。

### 第 2 章 DEPLOY — 选址安装
- 场景: 一幅横向社区剖面图(SVG/canvas 手绘): 自家屋顶、后院烧烤炉旁、临街车道边、
  离地 1.5m 的开阔外墙(正确)、室内窗台。5 个候选点位可点击,每个点位 hover 显示环境提示
  (温度、气流、污染源距离)。
- 选定后节点图标安放到位,显示 GPS 坐标(虚构但格式真实)。
- 后果注入: 屋顶 → 白天高温虚低 + 大风稀释; 烧烤炉旁 → 晚饭时段规律性尖峰(周期性偏差,第 4 章散点图上形成一簇离群点); 车道边 → 早晚高峰尖峰; 室内 → 与室外站相关性极低。开阔外墙 → 干净基线。
- 任何点位都能进第 3 章 —— 选址偏差是第 4 章诊断循环的素材,不在本章拦截。

### 第 3 章 OPERATE — 运行 30 天(核心章)
- 场景: 节点仪表盘。布局: 顶部 NowCast AQI 大表盘(EPA 六色带) + 当前 PM2.5 原始/校正双值;
  中部 30 天滚动折线图(canvas, 原始灰线 / 校正彩线 / RH 虚线三条); 底部事件日志卡片流。
- 时间机制: 1 秒 ≈ 2 小时,可暂停 / 1x / 4x 快进。30 天 = 720 个模拟小时点。
- 数据引擎(核心,必须真算):
  - 基线: 昼夜双峰(早晚高峰 +8~15 μg/m³) + 缓慢随机游走 + 白噪声。
  - 事件脚本(顺序固定、日期轻度随机): 第 5-7 天 湿雾天(RH 90%, 原始读数虚高 ~1.6x);
    第 12 天 大风清洁日(PM 降到 3-6); 第 18-20 天 野火烟雾日(PM 冲到 150-250, AQI 进紫色段);
    每天 18-20 时若选址在烧烤炉旁注入 +40 尖峰。
  - 湿度虚高机理: 原始值 = 真实值 × (1 + k×max(0,RH-60)/40),模拟激光散射把吸湿长大的颗粒算大。
- 玩家任务 — "写"校正管线(游戏化为装配三块管线卡,拖/点入数据流水线插槽):
  1. `EPA 校正` 卡: PM2.5_corr = 0.524×raw − 0.0862×RH + 5.75 (真实 Barkjohn 公式,guide 注明来源)
  2. `NowCast` 卡: 12 小时加权滚动平均, w* = 1 − (c_max−c_min)/c_max, w = max(w*, 0.5),
     NowCast = Σ(w^i·c_i)/Σ(w^i) —— 装上前 AQI 表盘用"原始 1 小时值"跳变,装上后变平滑,
     烟雾日能直观看到 NowCast 对突变的快速响应(w 变小 → 重视新数据)。
  3. `AQI 换算` 卡: EPA 2024 PM2.5 分段线性插值(0-9.0 绿 / 9.1-35.4 黄 / 35.5-55.4 橙 /
     55.5-125.4 红 / 125.5-225.4 紫 / 225.5+ 褐)。
  - 三卡未装齐时表盘显示"RAW ONLY"徽标,数据仍在跑 —— 允许玩家先裸跑几天再补管线,
    补装后历史曲线即时重算(重算就是重跑一遍纯函数,体现"管线是纯函数"的工程观)。
- 烟雾日特殊演出: 天空背景色渐变到橙褐,事件卡要求玩家写一行事件日志(点选式填空),
  这条日志会出现在第 4 章的验证报告里。

### 第 4 章 VALIDATE & PUBLISH — 交叉验证与上图
- 场景 A — 验证台: 左散点图(x=AirNow 官方站逐时值, y=我的节点校正值, canvas 绘制,含 y=x 参考线),
  右指标面板: 相关系数 r、MAE、平均偏差 bias,全部由第 3 章真实累积的 720 点数据计算。
  AirNow 官方序列 = 真实值序列 + 站点距离噪声(即数据引擎里的"真实值"加小噪声,玩家不可见此实现)。
- 达标线(镜像 EPA 性能目标): r ≥ 0.90 且 MAE ≤ 5 μg/m³。
- 诊断循环(不达标时): 指标面板给出线索芯片,点击展开诊断 —— 未装 EPA 校正卡 → "阴雨天散点整体
  在 y=x 上方弯起"; 接线错误 → "散点无结构(乱码),回第 1 章检查 UART"; 烧烤炉选址 → "18-20 时
  的点单独成簇偏高,回第 2 章迁址"; 密封外壳 → "散点滞后成环"。修复动作: 补装管线卡(即时重算)、
  回工作台改线、迁址(迁址后重跑最近 7 天,快进演出 5 秒)。修好 → 重新计算指标。
- 场景 B — 上图仪式(达标后解锁): 视角从仪表盘拉远到 PurpleAir 风格区域地图(canvas 手绘海岸线 +
  街区网格 + 约 90 个按 AQI 着色的社区传感器圆点),玩家的节点脉冲点亮,弹出注册卡: 节点 ID、坐标、
  "PUBLIC · LIVE" 徽标; 随后 Zenodo 数据集卡打出 DOI 号(格式 10.5281/zenodo.XXXXXXX);
  最终结算卡: 30 天数据完整率、r、MAE、处理过的事件数、工程决策回顾(哪些一次做对/哪些返工)。
- 结算后开放"自由运行"模式: 时间继续走,可随意触发烟雾日/大风日观察系统响应(供反复把玩)。

## 3. 侧栏(200px 标准布局,复用现有 game 契约)

- brand 块: `AIR NODE / 空气质量节点` + 项目代号 `ENV-10`。
- `#langBtn` 中/EN 切换(全部文案 data-i18n 双语)。
- roadmap: 4 章节点(BUILD / DEPLOY / OPERATE / VALIDATE),当前章金点脉冲,完成章实心。
- task 卡: 当前章目标一句话,动态更新。
- guide 块: 当前章操作提示 + 一条"为什么"知识点(如 UART 为何交叉、NowCast 为何加权)。
- endmark: 状态行,JetBrains Mono,显示模拟时钟 `DAY 12 · 14:00` 与数据点计数。

## 4. 视觉规格

- 视口: 固定 1280×800 设计视口(meta width=1280),body 100vw/100vh overflow hidden,
  外层由前端 ScaledIframe 等比缩放 —— 不做响应式。
- 基底: 深空共享画布(--bg-0: oklch(0.14 0.035 265) 系列),主题色板 env-10 生态穹顶:
  CANOPY oklch(0.72 0.15 140) / LOAM oklch(0.52 0.13 140) / ABYSS oklch(0.35 0.10 140) /
  DAWN oklch(0.92 0.08 140) / SUN oklch(0.85 0.14 85)。
- AQI 六色为功能色特例(EPA 语义色,允许突破色板): 绿 黄 橙 红 紫 褐,用 oklch 定义并降饱和
  以贴合深色主题。
- 数字/HUD/坐标一律 JetBrains Mono(带系统等宽兜底),正文 Inter/PingFang SC。
- 硬边框 1.5px + 3px 硬阴影按钮(与现有 game 一致),禁止圆角软阴影玻璃拟态。
- 禁止任何 emoji / Unicode 装饰符号,图形一律 SVG/canvas 手绘。
- canvas 的直接父容器必须 display:flex + flex-direction:column(shim flex 契约)。
- 顶层禁用 history/location/name/status 等 window 同名变量。

## 5. 技术规格

- 单文件 HTML,零外部依赖,内联全部 CSS/JS。代码量不限,以表达清楚为准。
- 状态机: `S = {chapter, wiring:{uartCrossed,bmeOk}, enclosure, site, pipeline:{corr,nowcast,aqi},
  clockHour, series:{raw[],truth[],rh[],corr[],nowcast[]}, events[], metrics:{r,mae,bias},
  published, lang}`。
- 数据引擎与管线全部写成纯函数(genTruth(h), distort(truth,ctx), applyCorr(raw,rh),
  nowcast(window12), aqiFromConc(c), pearson(a,b), mae(a,b)),重算 = 重跑纯函数。
- 折线图 / 散点图 / 世界地图均为 2D canvas 手绘,devicePixelRatio 适配。
- i18n: 所有文案存 `T = {zh:{...}, en:{...}}`,langBtn 切换即时刷新。
- 文字排布逐对检查不重叠(尤其表盘数值 vs 色带标签、散点图轴标 vs 图例)。
