> 用途: 项目级(而非 knode 级)交互模拟游戏。一个项目一个 HTML,整体模拟该项目的**最终产出物**,
> 让学生在开始学习前就"玩到"自己 61 周后将做出的东西。
> 本文件是给实现者(Claude Code)的完整设计规格,实现时严格遵循。
> 范式基线: 复用已验证的 purpleair / satellite_archaeology 两份 prompt 的全部工程契约
> (两步流程、真算数值、决策留后果、诊断循环、深空共享画布、单文件零依赖、中英双语、1280×800)。
> 本文件只详述本项目独有的设计。

## 0. 项目背景(来自 blueprint)

- 项目: 3D 打印肌电义肢手 — 用你自己的肌肉信号 (sEMG) 控制你打印的一只手, 10-12 岁, 61 周, 难度 4/5。
- 真实原型: Open Bionics Hero Arm (商用 3D 打印肌电义肢) + e-NABLE 全球志愿者网络;
  传感器 DFRobot/OYMotion Gravity Analog EMG SEN0240 (把 ±1.5 mV 皮肤表面信号放大 1000 倍);
  腱驱动 (穿过手指的线, 拉紧则弯曲) = 真实义肢与波士顿动力手同款执行方式。
- 最终产出物: 一只**你自己打印的、贴在前臂上、跟着肌肉发力开合抓握的仿生手** —— 手掌/五指/
  指内腱道全部你打印, 鱼线当腱, 五个舵机驱动, 前臂 sEMG 传感器读你的"握拳"信号, 经
  去噪→整流→平滑→阈值/比例控制驱动手开合, 能跑完整"贴电极→握拳→抓起物体→放松→放下",
  并用一张"EMG 信号 vs 实测握力"同步曲线证明手真的跟随肌肉。
- 核心科学链 (分层, 全部可真算):
  原始 EMG (±1.5mV 交流, 均值≈0) → 整流 (取绝对值) → 滑动平均平滑 → 归一化 0-100% →
  阈值/迟滞决策 → 比例控制映射到舵机角度 → FSR 指尖力传感 → PID 力闭环 (握住但不捏碎)。
- 独有维度: **实时人机闭环 + 物理执行末端 (手指舵机) + 力反馈 PID 控制**; 高潮是**鸡蛋实验**
  (调目标力到"握得住但不捏碎")—— 顺应性力控制, 比前两个项目的"验证达标"更有张力。

## 1. 游戏定位与核心幻想

**名称**: 肌电义肢手 / Myoelectric Hand
**核心幻想**: 你是一名义肢工程师学徒。从一段杂乱的肌肉电信号出发, 亲手把它净化成一条干净的
"发力强度"曲线, 教这只你打印的手读懂你的"握拳"意图, 再加上指尖力反馈让它学会**握住鸡蛋而不捏碎**,
最终贴上传感器、握拳, 让这只手跟着你的肌肉抓起东西再放下 —— 证明它真的听你的肌肉指挥。

**"部署到应用环境"的映射 (本项目的关键)**:
产出物是一只实体会动的义肢手, 它的"应用环境"= **戴在前臂上、肌肉发力、手指实时响应、抓真实物体**。
玩家操作的对象就是这条从皮肤电信号到手指动作的**实时控制链**和它抓取物体的物理结果:
- 部署 = 把整条信号链接通到手上, 贴电极、握拳, 手实时跟随 (第 4 章)。
- 环境反馈 = 手指弯曲、腱线张紧、抓住/滑落/捏碎、FSR 力曲线、EMG-力同步图。
这与 purpleair 的物理部署、satellite 的数据科学部署都正交 —— 它是**实时的、闭环的、有物理执行末端、
人在回路里的**。证明范式能覆盖"实时控制/机器人"类产出物。

**设计原则**:
1. 模拟的是**产出物**, 不是课程知识点 —— 玩家操作的是这条 EMG→手的控制链和它抓取的物理结果。
2. 所有数值必须**真算**: EMG 波形合成、整流、滑动平均、归一化、阈值/迟滞、比例映射、
   舵机角度→手指弯曲运动学、FSR 力、PID (P/I/D 三项) 全部用真实公式在 JS 里逐采样点计算,
   手的姿态与抓取结果由物理真实推导, 不做假动画。
3. 玩家的**每个决策都留下后果**: 电极贴错位 → 信号弱/噪声大; 不整流 → 均值≈0 无法用;
   平滑窗口太小 → 手抖动, 太大 → 反应迟钝; 阈值太低 → 误触发乱抓; 无迟滞 → 边界颤动;
   直接驱动无力反馈 → 捏碎鸡蛋; PID 没调好 → 力超调 (捏碎) / 稳态误差 (握不紧滑落)。
   后果实时以手的行为 + 曲线显形, 允许回头修 (镜像 W46 抖动→W47 平滑→W48 限速→W50-53 PID 循环)。
4. 失败不是终局而是诊断入口: 抖动/误抓/捏碎/滑落时给出可交互诊断芯片, 修复后重试。
5. 鸡蛋实验是硬高潮: 力控不当会**当场捏碎鸡蛋**(演出) 或**物体滑落**, 必须调好 PID 力闭环
   才能"握住不碎"通关。

## 2. 章节结构(镜像项目 8 个 Phase, 压缩为 4 章)

单页四章连续推进, 侧栏 roadmap 显示进度。全程一个存档状态对象 `S`, 前章决策影响后章。
四章: SIGNAL(信号) → INTENT(意图) → HAND(手) → GRASP(抓取)。
(项目 8 phase → 游戏 4 章映射: P1-3→SIGNAL 信号链; P4→INTENT 决策; P5-6→HAND 造手+舵机;
P7-8→GRASP 力闭环+集成验证。)

### 第 1 章 SIGNAL — 净化肌肉电信号 (对应 Phase 1-3: 读 EMG + 信号处理链)
- 场景: 示波器 + 信号处理流水线。顶部实时波形示波器 (canvas 滚动), 中部一条**可组装的处理管线**
  (原始 → [整流] → [平滑] → [归一化] 四个插槽), 底部"发力强度"输出条 (0-100%)。
- 交互 A — 电极贴放: 一幅前臂剖面图 (canvas 手绘), 3 个电极 (信号/参考/地) 要拖到正确肌腹位置
  (前臂屈肌群)。贴错位置 (贴到骨头上/贴太近) → 原始信号幅度小、噪声大 (后果注入, 不当场拦截)。
  正确位置 → 干净的握拳爆发信号。guide 点破差分电极几何 (为什么要 3 个、信号-参考做差抑制共模)。
- 交互 B — "握拳"手势: 一个可按住的"握拳"按钮 (或空格键), 按住时肌肉发力, EMG 爆发;
  松开则回到基线。玩家按节奏握拳/放松, 观察波形。
- 数据引擎 (核心, 必须真算):
  - 原始 EMG: 基线噪声 + 握拳时的高频爆发 (随机相位正弦簇, 幅度随发力强度), **均值≈0 的交流信号**。
    raw(t) = effort·burst(t)·carrier(t) + noise(t) + mains50(t); carrier 为高频, mains 为 50Hz 工频。
  - 电极位置影响: 贴错 → effort 系数衰减 + noise 抬升 + mains 增强。
- 玩家任务 — 组装信号处理链 (拖/点四块卡入插槽):
  1. `整流` 卡: rect = |raw| (取绝对值, 把负半周翻正)。装上前波形上下对称均值≈0, 装上后全正。
  2. `平滑` 卡 (带窗口大小滑杆 N): smooth[i] = mean(rect[i-N+1..i]) (滑动平均)。
     N 太小 → 曲线仍抖 (后果: 第 3 章手抖); N 太大 → 曲线迟钝滞后 (后果: 手反应慢)。
  3. `归一化` 卡: 需先"标定"—— 记录放松基线 + 全力峰值, strength% = clamp((smooth−base)/(peak−base)·100, 0, 100)。
  4. (可选) `50Hz 陷波`: 玩家若识别出 50Hz 抖动可加, 显著降噪 (差分电极也能减, 形成认知对比)。
  - 未装齐时输出条显示"RAW" 徽标; 装齐后"发力强度"变成一条干净的 0-100% 曲线。
- 通过条件: 整流 + 平滑 + 归一化三卡装齐且完成标定, 输出一条可用强度曲线, 点"进入决策"。
- guide 知识点: 为什么不能直接用原始信号 (交流均值 0); 整流/滑动平均的物理意义; 50Hz 工频从哪来。

### 第 2 章 INTENT — 从信号到意图决策 (对应 Phase 4: 阈值/迟滞/误触发)
- 场景: 强度曲线 + 决策可视化。上半实时强度曲线上叠加**可拖动的阈值线** (无迟滞时一条,
  加迟滞后上下两条); 下半"意图"指示灯 (CLENCH / RELAX) + 一个滚动的误触发计数板。
- 交互 A — 设阈值: 拖动阈值线。太低 → 放松时的噪声也越线 (误触发 false positive);
  太高 → 轻握不触发 (漏检 false negative)。实时统计: 让玩家做 20 次握拳/放松试验 (脚本化 + 手动),
  真算命中率 / 误触发率 / 漏检率, 显示在计分板。
- 交互 B — 迟滞 (hysteresis): 加"上阈值/下阈值"双线 —— 越过上线才算 CLENCH, 跌破下线才算 RELAX,
  之间保持。消除边界颤动 (chatter)。装上前边界处指示灯疯狂闪 (chatter 演出), 装上后稳定。
- 交互 C — 去抖 (debounce): 必须连续 N 采样超阈才确认, 滤掉毛刺误触发。
- 数据引擎: 复用第 1 章强度曲线; 决策 = 阈值 + 迟滞 + 去抖的纯函数, 逐采样点判定 intent。
- 通过条件: 命中率 ≥ 90% 且边界无 chatter (加了迟滞) → 点"进入造手"。
- 诊断: 误触发多 → 提示"阈值太低 / 加去抖"; 漏检多 → "阈值太高"; 指示灯颤动 → "加迟滞"。
- guide: 阈值/误报漏报权衡; 迟滞为何消除颤动; 去抖的作用。

### 第 3 章 HAND — 造一只腱驱动的手 + 舵机标定 (对应 Phase 5-6: 3D 打印手 + 舵机)
- 场景: 一只 2D 侧面**腱驱动手** (canvas 手绘: 手掌 + 五指, 每指 3 节指骨 + 关节, 一条腱线
  从指尖穿过关节连到手腕的舵机盘; 一条弹性回位线)。右侧舵机控制台。
- 交互 A — 腱驱动原理 (手动): 先给一根"手动拉线"滑杆, 拉线 → 手指按运动学弯曲 (腱线张紧,
  各关节按比例弯曲), 松线 → 弹性回位伸直。建立"拉腱→弯曲"的直觉。
- 交互 B — 材料选择: PLA (刚性, 关节需铰链) vs TPU (柔性, 关节可直接弯)。选 PLA 无铰链 →
  手指弯曲卡顿 (后果); TPU 或 PLA+铰链 → 顺滑。(轻量演出, 不深挖。)
- 交互 C — 舵机驱动 + 标定: 用舵机替代手动拉线。舵机角度 (0-180°) → 通过 PWM 脉宽编码 →
  拉动腱线 → 手指弯曲量。玩家要**标定**: 记录"舵机角度 ↔ 手指弯曲度"映射 (采几个点连成曲线),
  标定不准 → 第 4 章比例控制映射偏 (手抓过头/抓不到)。
  - 扭矩预算 (轻量): 一个提示牌算"一个舵机能否拉动五指" (欠驱动/差动), 不做深交互。
- 数据引擎 (真算): 手指运动学 —— 给定腱线位移 d, 各关节角 θ_j = f(d) (简单比例 + 关节限位);
  指尖位置由正向运动学 (连杆累加) 算出; 舵机角 → 脉宽 → 腱位移的标定曲线为分段线性。
- 通过条件: 舵机装上 + 完成标定 (至少 3 点), 手能从舵机角度命令开合 → 点"接入肌肉信号"。
- guide: 腱驱动原理; PWM 脉宽↔角度; 为什么要标定 (命令值 vs 实际弯曲的映射)。

### 第 4 章 GRASP — 肌电力闭环 + 抓取验证 (核心章, 对应 Phase 7-8: PID 力控 + 集成)
- 场景: 完整系统台。左侧那只手 (第 3 章的手) + 一个可选物体 (鸡蛋 / 塑料杯 / 钢块);
  右侧三条实时曲线 (EMG 强度 / 舵机角度命令 / **实测握力 FSR**) + PID 控制台 (P/I/D 三个滑杆)。
  顶部"贴电极→握拳"控制 (复用第 1 章握拳按钮 + 电极状态)。
- 交互链 (逐步解锁, 镜像 W45-55):
  1. **开环直驱** (W45): EMG 强度直接映射舵机角度。握拳 → 手跟随闭合。但…
  2. **抖动显形** (W46): 直驱下手**抖动/过冲** (强度曲线的残留噪声直接传到手)。诊断入口。
  3. **输出平滑 + 限速** (W47-48): 加输出平滑 + 速率限制 (每步最大移动量) → 手动作变柔顺。
  4. **接入力反馈** (W49): 指尖 FSR 开始读**实测握力** (手指接触物体后力上升)。力成为真实反馈变量。
  5. **比例控制 P** (W50): 目标力 vs 实测力的误差 → 驱动闭合速度 (误差大快合, 接近目标力减速)。
     只有 P → 接近目标力时**稳态残差** (握不到目标力, 易滑落) 或**超调** (冲过头, 捏碎)。
  6. **加 D 抑制超调** (W51): D 项 (力变化率) 抑制冲过头 → 减少捏碎风险。
  7. **加 I 消稳态误差** (W52): I 项累积残差 → 最终稳稳达到目标力。
  8. **PID 合调** (W53): 三滑杆合调, 追求"快且稳"的力控。
- **鸡蛋实验** (W54, 高潮): 选鸡蛋物体。目标力设太高或 P 过大/无 D → **鸡蛋当场捏碎** (裂纹演出 + 失败);
  目标力太低或稳态误差大 → **鸡蛋滑落** (掉落演出 + 失败); 力控调好 (握力稳定落在"握得住不捏碎"
  的安全窗口内) → **鸡蛋完好握住** (通关)。安全窗口是真实力区间 [f_hold, f_crush], 由物体决定。
- 数据引擎 (真算, 全部逐帧):
  - 手接触物体后, 握力 F 随手指闭合量上升 (接触刚度模型): F = k·max(0, closure − contactPoint)。
  - PID: e = F_target − F_meas; u = Kp·e + Ki·∫e + Kd·de/dt; u 经限速/平滑驱动舵机角 → closure → F。
  - 物体判定: F > f_crush → 碎/坏; F < f_hold 且尝试提起 → 滑落; f_hold ≤ F ≤ f_crush → 稳握。
  - EMG 强度在这里作为**目标力的设定** (握得越用力目标力越高) 或触发抓取, 体现"肌肉意图→力"。
- 交互 D — 端到端演示 (W57): 一键"贴电极 → 握拳 → 抓起鸡蛋 → 放松 → 放下", 手完成全动作,
  三条曲线同步滚动。
- 结算仪式 (通关后): **EMG 信号 vs 实测握力同步验证图** (双曲线叠加, 证明力闭环真跟随肌肉且
  稳定在目标力), 打出**产出物卡**: 完好的鸡蛋、最终 PID 参数、命中率、力控稳态误差;
  产出徽章: 开源手模型 remix (Thingiverse 风) + 代码仓库。
  结算卡工程决策回顾 (哪些一次做对/哪些返工: 电极位置、平滑窗口、迟滞、PID 调参、是否捏碎过鸡蛋)。
- 结算后开放"自由抓取"模式: 换物体 (鸡蛋/纸杯/钢块/水球), 各有不同安全力窗口, 反复练力控。

- 顶层禁用 history/location/name/status 等 window 同名变量。
- 文字排布逐对检查不重叠 (尤其示波器轴标、三曲线图例、PID 滑杆标签、力值 vs 安全窗标注)。

## 5. 技术规格

- 单文件 HTML, 零外部依赖, 内联全部 CSS/JS。代码量不限, 以表达清楚为准。
- 实时循环: requestAnimationFrame 驱动一个固定步长的仿真时钟 (如 dt=1/60 或采样 200Hz 的分频),
  可暂停 / 慢放。EMG 波形滚动、手的物理、PID 都在这个 tick 里逐步推进。
- 状态机 (建议形态, 实现可增补):
  ```
  S = {
    chapter, lang,
    electrodes:{signal,ref,gnd, placedOk},   // 第1章电极位置正确性
    clenching,                                // 握拳按钮是否按下
    pipeline:{rect,smooth,norm,notch}, smoothN, calib:{base,peak,done},
    threshold, hyst:{on,hi,lo}, debounceN,    // 第2章决策
    hitStats:{tp,fp,fn,trials},
    hand:{material, servoCalib:[], closure, jointAngles:[]}, // 第3章手
    ctrl:{mode, outSmooth, rateLimit, Kp,Ki,Kd, targetForce}, // 第4章控制
    object, force, integ, prevErr,            // 第4章力闭环运行时
    result:{grasped,crushed,dropped}, freeMode,
    // running signal buffers
    rawBuf[], rectBuf[], smoothBuf[], strengthBuf[], forceBuf[], angleBuf[],
  }
  ```
- 纯函数 (真算, 与前两试点同哲学):
  - `hash01/n11/smoothstep` — 同款确定性噪声原语。
  - `emgRaw(t, effort, elecOk)` — 合成原始 EMG (爆发载波 + 基线噪声 + 50Hz 工频, 均值≈0)。
  - `rectify(x)=|x|`; `movAvg(buf,N)`; `normalize(v,base,peak)` — 信号链三段。
  - `decide(strength, thr, hyst, debounce, state)` — 阈值/迟滞/去抖决策, 返回 intent。
  - `fingerKinematics(tendonDisp)` — 腱位移→各关节角→指尖位置 (正向运动学连杆累加 + 限位)。
  - `servoToTendon(angle, calib)` — 舵机角经标定曲线→腱位移 (分段线性)。
  - `contactForce(closure, obj)` — 接触刚度模型算握力。
  - `pidStep(target, meas, {Kp,Ki,Kd}, state, dt)` — 逐帧 PID, 返回控制量 + 更新积分/微分状态。
  - 物体安全窗 `[f_hold, f_crush]` 每物体一组常量, 判定 grasped/crushed/dropped。
- 示波器/三曲线图/手/前臂电极图/PID 响应均为 2D canvas 手绘, devicePixelRatio 适配。
- i18n: 所有文案存 `T = {zh:{...}, en:{...}}`, langBtn 切换即时刷新。
- 暴露 window.S 及关键函数便于调试/自动化测试 (与 satellite 试点一致)。
