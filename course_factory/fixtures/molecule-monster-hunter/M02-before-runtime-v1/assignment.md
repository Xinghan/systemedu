## 一、选择题（4题）

**1. 代码世界里的“工具包(库)”，最像下面哪种东西？**
A. 一本字典
B. 一整套别人已经做好、你装上就能直接用的现成工具箱
C. 一道考试题
D. 一个游戏关卡
**答案：B**

**2. 把 RDKit“装到电脑里”这件事，正确的理解是？**
A. 把它打印在纸上
B. 用一条命令（如 pip install rdkit）把这个工具箱下载配置到你的电脑里，之后随时能用
C. 在脑子里记住它
D. 把它画成一张图
**答案：B**

**3. 在代码里写 `import rdkit` 这一行，最贴切的意思是？**
A. 把 RDKit 删掉
B. 把已经装好的 RDKit 工具箱“请到”当前这段代码里，这样才能用它的本领
C. 重新下载一次 RDKit
D. 给 RDKit 改名字
**答案：B**

**4. RDKit 已经装好了，但你不写 import 就直接让它画分子，会怎样？**
A. 照样能用
B. 电脑会报错说“不认识 rdkit”，因为当前这段代码还没把它请进来
C. 电脑会自动帮你 import
D. 分子会画错
**答案：B**

## 二、问答题（2题）

**1. 用你自己的话说说：“安装(install)”和“导入(import)”有什么不一样？用“储物间”和“工作桌”的比方解释一下。**
（参考要点：安装是把工具箱**一次性**从网上搬进电脑、放进“储物间”，长期存在那里；import 是**每一段要用到它的代码**开头，把工具箱从储物间搬到当前的“工作桌”上，请进来之后才能用它的本领。所以先有安装、后有 import；装好了不 import 还是用不了（电脑会说“不认识它”），没装就更别提 import 了。一句话：装 = 进储物间一次就够；import = 每次用前搬上桌。）

**2. 这一节为什么用“让 RDKit 打印出版本号”来检查环境装好没？打印出版本号说明了哪几件事都成功了？**
（参考要点：打印版本号是检查环境最小、最安全的一步——不需要任何复杂操作。只要 `import rdkit` 后能成功打印出它的版本号，就一连证明了三件事都成了：① RDKit **安装**成功了；② 它能被成功 **import**（请上工作桌）；③ 它的信息能被正常**读取**。所以工程上常把“打印版本号”当作“环境就绪”的第一道检查，这也是本节的验收标准：一次成功的 import + 一个打印出来的版本号。）

## 三、动手项目

[HANDS_ON] 在家长协助下装好 RDKit，跑通第一行，记下版本号

⚠️ 装软件、敲命令请**和家长一起做**。我们用本地的 Anaconda / Jupyter 为主。分三步：

1. **装工具箱**：按老师给的现成命令（通常就一句 `pip install rdkit`）把 RDKit 装上。装的过程要等一小会儿，那是电脑在帮你把工具箱搬进“储物间”。
2. **请它进门**：打开一个能写 Python 的地方（命令行或 Jupyter），敲 `import rdkit`——把工具箱从储物间搬上你的工作桌。
3. **让它报个到**：再敲一句 `print(rdkit.__version__)`，如果屏幕上跳出一个版本号（比如一串像 2024.03 的数字），恭喜你，**第一行跑通了**，工具箱装好能用了。

完成标志：一张**屏幕截图**（或抄下来的那个版本号），证明你成功 `import` 了 RDKit 并让它报出了版本号。把它存进你的项目文件夹——这是你工作台搭起来的第一个证据。

**温馨提示**：安装中途遇到报错（红色的字）别慌，那很正常，连专业程序员都天天遇到。和家长一起，把那行红字读一读、上网查一查、再试一次，往往就过去了。能不慌不忙地读报错、解决它，本身就是程序员最重要的本事之一。
