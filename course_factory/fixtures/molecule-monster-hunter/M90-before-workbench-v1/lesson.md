# 组装 Workbench 出最终 go/no-go 报告(全课终点)

### 这一步在通向哪 (北极星)

**我们最终要做出的**: 一台分子怪兽猎人工作台——你输入一个分子, 它画出结构、预测属性(好不好溶、有没有毒、能不能成药)、打分排序、给出 go/no-go 的理由, 并从几千个分子里替你筛出最值得试的前十名。

**这一节你亲手做出的那块积木**: 就是上面这台工作台**本身**——这一节, 你把这一整门课里一件一件做出来的零件, 第一次**全部接到一条线上**, 装成一个能真正跑起来的成品。你输进去一串 SMILES, 它自己一路走完: 画结构图、算特征、用模型预测属性、过一层层漏斗、打分排序、给每个候选一句 go 或 no-go 的理由, 最后吐出一份候选报告——里头写着对模型最不留情那种考法(scaffold 划分)下算出来的**真实** ROC-AUC / MAE、每个分子的 Lipinski 成药门槛, 还有挑出来的 Top10。这一节不要求你从零写代码, 给你一套能跑的完整模板, 你只填几个空、改一两个参数、按下运行(这一节需要家长陪你一起跑)。

**它通向**: 这就是终点。前面所有关——画分子、建库、算特征、训模型、做漏斗、写理由——都是在为这一刻攒零件; 这一节把它们合体, 你这门课要做的那台工作台, 到此**真的站起来、能用了**。

**离终点还差几步**: 零步——你正站在终点上。这是"怪兽挑战"这一关(S5)的收口, 也是整门课的收口。装完、跑通、出报告, 你就从一个只会单点本事的人, 变成了一个**能把一整条流水线攒成产品**的人。

## 这一节你要拿下的

- 弄懂**流水线总装**是怎么回事: 不是再做一遍零件, 而是把各管各的零件**按顺序接成一条能自己跑完的线**, 关键全在接口对不对得上。
- 弄懂一份 **go/no-go 报告**该长什么样: 对每个候选给一个干脆的"上 / 不上", 而且**带着证据和理由**, 不是光秃秃一个结论。
- 把这门课的零件——结构图(M05)、特征表(M53)、诚实模型包(M84b)、多层漏斗(M86-M88)、拒绝理由(M89)——接成一台能跑的工作台。
- 跑出一份**诚实**的候选报告: scaffold 划分下的真实 ROC-AUC / MAE、Lipinski 门槛、Top10, 哪怕分数难看也照实写。

## 引入: 怎么把这一路做的全部, 组装成一个能用的分子猎人工作台?

> 我能把这一整门课做出来的所有零件, 总装成一台输入 SMILES 就能跑出结构图、预测、打分、go/no-go 理由和 Top10 的工作台, 并让它出一份诚实的候选报告吗?

停下来想一件事: 到这一节为止, 你其实**什么本事都已经会了**。你会让 RDKit 把 SMILES 画成结构图, 会给分子算出一排特征, 会训一个能预测属性又不吹牛的模型, 会用 Lipinski 和多层漏斗一层层筛, 会给每个被刷下来的分子写一句理由。一样都不缺。

可是——它们一直是**散的**。结构图在一个脚本里, 特征在另一个脚本里, 模型、漏斗、理由各待各的文件。你想用一次, 得把五六个步骤挨个手敲一遍, 跑一个分子就累得够呛, 更别提几千个。这一节要回答的就是这个问题: 怎么把这些各管各的零件, **接成一条线**, 让一个分子从这头丢进去, 那头自己就走出一份完整报告?

这件事有两个真正的难点, 都不在零件本身, 而在"怎么接"和"接完信不信得过"。

换个角度看, 你这一节做的事跟工厂里"上生产线"是一回事。一家工厂请来六个老师傅, 每个人手艺都顶呱呱: 一个会铸件、一个会打磨、一个会喷漆。可只要这六个人各做各的、谁也不挨着谁, 工厂就还造不出一件成品——它只是六间各忙各的作坊。真正让它变成工厂的, 是有人把六道工序按顺序排成一条传送带, 让半成品从这头进、那头出, 中间不用谁喊一嗓子"轮到你了"。你前面几十节课, 已经把六个老师傅一个个请齐了; 这一节你要做的, 就是把传送带架起来, 让分子怪兽猎人这家"工厂"第一次真正开工。这也是为什么这一节被排在全课的最后——它不是又教你一门新手艺, 而是把你已有的全部手艺拢成一个能交付的东西, 是一次"合体", 是毕业作品。

而且要提醒你一句: 把零件接成线, 看上去好像只是"把已经会的东西串起来"这种轻松活, 其实它本身就是一门真本事, 在工业界有专门的名字叫"流水线工程"。能写出某一道工序的人很多, 能把好几道工序稳稳当当接成一条不会在半路出岔子的线、还让它经得起反复跑的人, 要值钱得多。你这一节练的, 正是这门本事的入门。把它学扎实, 往后你不管做什么项目, 只要涉及"把好几步串成一条能自动跑的流程", 用的都是今天这套思路——先理清每一步交给下一步的是什么、下一步又要的是什么, 再一段一段稳稳接上、一段一段试着跑通。这是一套能跟你走很远的真功夫, 不只是为了今天这一台分子工作台。

## 总装: 把各管各的零件接成一条能跑通的线

[[THEORY:pipeline_assembly]]

第一个难点是**接**。把零件接成流水线, 真正要盯的不是每道工序本身——那些你早练熟了——而是两道工序之间的**接口**: 上一道吐出来的东西, 是不是正好下一道张嘴要的东西。

照这个顺序把线接起来。**第一道**, 收一串 SMILES, 先用 RDKit 逐条读通, 把读不出来的脏字符串挡在门外(不然它会让后面每一道都崩), 顺手画出结构图。**第二道**, 给读通的分子算出那一排特征——这里有个**最致命的坑**: 喂给后面模型的特征, 必须跟当初训模型时**完全同一排、同一个顺序**, 少一列或换了序, 模型就会把油水性当成分子量去理解, 预测全错还偏偏不报错。**第三道**, 把特征喂进诚实模型包, 预测好不好溶、有没有毒。**第四道**, 把预测结果和 Lipinski 门槛送进多层漏斗, 一层层筛、综合打分、排序, 选出 Top10。每接好一道, 就拿一个你知道答案的分子(比如乙醇)走一遍, 看接缝处对不对得上, 再接下一道——别一口气全接完才跑, 那样错藏在哪你根本找不着。

这里要专门把那个**最致命的坑**再掰开说一遍, 因为它最坑、最隐蔽, 八成的总装事故都出在这。模型当初学本事的时候, 是盯着一排排得整整齐齐的特征学的——第一列是分子量、第二列是油水性、第三列是某个指纹位……它把"第二列"和"油水性"死死绑在了一起。现在你接特征那道时, 万一算出来的特征少了一列、或者列的顺序排得跟训练时不一样, 模型可不知道, 它还是照着"第二列就是油水性"去理解, 结果你喂进去的"第二列"其实是分子量, 它就把分子量当油水性算了, 预测自然全错。最气人的是, 这种错**不会报错**: 那一排数字看上去仍然是合规的一排数字, 程序顺顺当当跑完, 给你一个看着挺像样、实则全错的结果。所以接到这一道, 你必须停下来, 把喂给模型的特征的列名和顺序, 跟训模型时记下来的那一份, 一列一列对清楚, 对上了再往下接。这一步多花的几分钟, 能帮你省下事后抓瞎几个钟头。

接通的那一刻, 你前面几十节课第一次**合体**成一个能反复用、自动跑的东西: 丢一个分子进去, 它哗啦一路走到底。这就是"工作台"和"一抽屉零散脚本"的根本区别——一个是能交到别人手上、别人也能跑的产品, 一个只是躺在你脑子里的一串操作步骤。

再说一遍"接口"这个词, 因为它是这一节最核心的一个概念。所谓接口, 就是两道工序碰头的那个交接面: 上一道把东西交出来, 下一道把东西接进去, 这两边得严丝合缝。你可以把它想成两个齿轮咬合: 齿对齿、缝对缝, 转起来才顺; 哪怕只差半个齿, 整台机器就卡住或者打滑。流水线里每两道工序之间都有这么一个交接面, 而你总装的全部功夫, 就花在让这些交接面一个个对齐上。具体到分子工作台, 你要盯的接口至少有这么几个: SMILES 读通那道交出去的, 必须是 RDKit 真能读懂的分子对象, 不能夹带读不通的脏字符串; 算特征那道交出去的, 必须是跟训练时同排同序的那一排数; 模型那道交出去的, 必须是漏斗看得懂的预测结果格式。每一个接口你都核一遍, 整条线才真正接得通、跑得稳。把这种"先核接口、再往下接"的习惯练成本能, 你以后接任何一条流水线都不会慌。

## 出报告: 把一路算出来的全部, 收成一句给人看的决定和理由

[[THEORY:go_no_go_decision_report]]

第二个难点是**信**。线接通了、能跑了, 还得让跑出来的东西**值得信**。这就靠最后那份 go/no-go 报告——对每个候选给一个干脆的"上 / 不上", 而且**带着证据和理由**。

报告里对每个分子, 该摊开给人看: 预测的属性、过没过 Lipinski 成药门槛、综合多少分、排第几, 以及最关键的——这个 go 或 no-go 到底是哪一条把它定下来的(这正是 M89 那一节给每个被拒分子写的那句理由的用处)。一份只给结论、不给理由的报告, 就像考卷只判对错不说错在哪, 没法让人信、也没法让人改。

而整份报告的命根子, 是**诚实**。衡量模型准不准, 必须用对它最不留情的考法——把训练和考试的分子**按骨架分开**(scaffold 划分), 不让它考到见过的近似分子——这么考, ROC-AUC / MAE 往往会往下掉, 但那个低一点的分数才是**真**的。你可以这么想: 要是考前把考题偷偷塞给模型看过(随机划分就容易这样, 测试集里混进了训练分子的近亲), 它考一百分也没用, 因为真上场遇到从没见过的新分子它就抓瞎了; scaffold 划分干的就是把考题和复习资料严格分开, 逼模型靠真本事考, 考出来的分虽然难看, 但那是它真上场能拿到的分。

这里最容易动歪心思: 分数不好看, 你会想美化它、想偷换个高分算法、想挑一个碰巧好看的随机种子。千万别。这份报告的全部价值就在它不骗人。想想后果就明白了: 这份报告是要拿去指导真实实验的, 而每做一个真实验都要花大钱、花好几个月。你要是把一个其实不行的分子吹成 go, 别人信了你, 把钱和时间全砸进去, 最后竹篮打水——这比你老老实实说"它不行"造成的损失大得多。所以这一节的达标线很特别, 跟前面任何一节都不一样: **只要工作台能跑通、报告如实含真实的 ROC-AUC / MAE / Lipinski / scaffold 划分, 就算做成了**——哪怕筛出来的 Top10 分数都一般、甚至没一个像样的, 只要这个结论是诚实算出来的、每个数字都经得起查, 这台工作台就成立。我们不拿分数高低评你的毕业作品, 只看你接通了没有、报告诚不诚实。宁可交一份难看但句句是真的报告, 也绝不交一份好看却骗人的——记住这一句, 它比这门课里任何一个公式都重要。

## 你今天要做的(总装工作台 + 出 go/no-go 报告)

1. **铺好流水线骨架**: 打开给你的工作台模板, 先别急着接, 花几分钟把它从头到尾看一遍, 看清它从 SMILES 入口到报告出口分成哪几道工序、每道工序留了哪个口子等你来接, 并在心里把每一道跟你前面学过的那一节对上号——读结构是 M05, 算特征是 M53, 跑模型是 M84b, 漏斗是 M86 到 M88, 写理由是 M89。心里有这张地图, 接的时候才不会乱。**[需家长协助]**
2. **接前半段(看得见的部分)**: 接通"SMILES → RDKit 读通并画结构图 → 算出那一排特征"。前半段叫"看得见的部分", 是因为它的产物(结构图、特征表)你都能直接看出来对不对。接这一段最要紧的一步是核对特征: 把工作台算出来的特征的列名和顺序, 跟当初训模型时存下来的那一份, 一列一列对清楚, 一个都不能差、一个都不能错位——这一步对上了, 后面才不会出那种"不报错却全错"的隐形事故。
3. **接后半段(会判断的部分)**: 把特征接进诚实模型包做预测, 再把预测结果和 Lipinski 门槛一起送进多层漏斗, 一层层筛、综合打分、排序, 选出 Top10。后半段叫"会判断的部分", 因为从这里开始, 工作台不只是在画、在算, 而是在替你做判断、下结论了。接这一段要留意的是: 漏斗的每一层筛的是什么、为什么这么筛, 你心里要清楚, 这样末端给出的每个结论你才说得清来由。
4. **跑通一个你知道答案的分子**: 拿一个熟分子(如阿司匹林或乙醇)从头丢进去, 确认它一路走完、每个接缝都对得上, 末端真的吐出结果。这一步是整条线的体检: 用一个你心里有数、大概知道结果该长什么样的分子去跑, 一旦哪里跑出来不对劲, 你立刻就能察觉, 而不是被一个陌生分子的怪结果蒙在鼓里。能记住的话, 边接边用它试, 比全接完再试省心得多。
5. **出诚实的 go/no-go 报告**: 让工作台在 scaffold 划分下算出真实 ROC-AUC / MAE, 给每个候选标上 go/no-go 和理由, 列出 Top10, 配上 Lipinski 门槛, 导出成一份候选报告。**分数难看也照实写**, 一个数字都别动——这是这份报告的命根子, 也是这一节真正的及格线。

做完这五步, 停下来回头看一眼: 你输进去的只是一串干巴巴的 SMILES, 末端却自己长出了一份带结论、带理由、带真实分数的完整报告, 中间你一道道接力都没插手。这就是一台工作台该有的样子, 也是你这门课从第一节学画分子起, 一直在朝着走的那个终点。到这里, 你不再是"会很多单点本事但还串不起来"的人了, 你成了一个能把一整条流水线攒成产品、还为它的诚实负责的人。这是值得郑重庆祝一下的一刻——你毕业了。回头看看这一路: 从第一节战战兢兢画出第一个分子, 到今天亲手把整条线接通、让它替你筛分子出报告, 你走过的每一节都不是白练的, 它们今天全都用上了、全都汇到这一台工作台里来了。这种"把学过的东西真正攒成一个能用的成品"的成就感, 值得你好好记住。
