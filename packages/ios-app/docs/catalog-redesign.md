# iOS 项目目录修订 · 2026-11-18

## 发现的问题

用户从首页点击“全部课程”，再选择项目时，目录高亮却没有进入详情。新增的 `testHomeCatalogOpensCourseAndReturns` 在修改前的 App 中复现失败，结果保存在 `build/catalog-regression-before.xcresult`。上一轮 UI 测试只从“探索”标签进入，没有覆盖首页入口。

首页原来用直接指定视图的 NavigationLink 打开 CatalogView，后续又用值导航打开 ContentCourse，目的地声明放在 CatalogView 内。两种导航混合导致值导航失去可用的目的地。Apple 的[导航栈说明](https://developer.apple.com/documentation/swiftui/understanding-the-navigation-stack)解释了混用时会弹出视图目的地；本次统一课程链路的值导航，在各标签根部注册唯一的 AppRoute 目的地。

另一个问题不是图片下载失败：上一版目录数据没有封面字段，原生列表也没有图片组件。既有图片虽然在包里，但从未用于课程目录。

## 布局与交互

考虑过双列海报、全宽大海报和带缩略图的横向卡片。长中文项目名称在双列中容易被截断，大海报会把可见的项目压缩到一两个，因此采用单列图文卡片：104 × 116 的封面、主题、项目名、类型、课节数；有记录时显示阅读进度。大字体模式改成纵向卡片，避免文字列过窄。

目录顶部始终保留搜索、主题和类型筛选。无匹配结果时可以一键清除筛选。卡片整个区域可点击，有按下反馈。标题使用系统圆角字体，正文使用系统字体，沿用暖白与深绿，锈色仅用于分类提示。间距使用 4 / 8 / 12 / 20，控件点击高度至少 44。

项目详情的上部是封面、项目名、介绍入口和阅读进度；中部只显示当前阶段的课节，阶段菜单可访问全部节点。底部固定“开始学习／继续学习”，无须滚到底部。横屏下把介绍、进度收进一行，同时显示课节和学习按钮；辅助功能大字号下收起封面，课节编号移到标题上方，为文字和操作保留空间。完整项目介绍按需打开，全部标题和说明都可读取。

“继续学习”只匹配同一课程和版本：未读完时回到最近的课节，标记读完后进入首个未读完课节。全部读完后可以继续复习。阅读进度明确写作“已读完”，不冒充正式成绩。

## 图片与数据

58 个项目全部产生本地 JPEG 封面。优先采用网站项目卡片的原图；没有登记独立封面的凌星、Transformer、后训练课程采用相应主题的既有场景图。TeachOpenCADD 使用共享课程源的封面。`coverSource` 记录每张图片的来源，`coverPath` 指向包内派生图片。960 × 640 的 JPEG 合计约 8.31 MB，原生异步解码并用有容量上限的缓存，避免滚动时读取大幅原图。

新增目录字段是兼容性扩展。58 个项目、843 个节点、所有版本、旧路由、正文和 SQLite 记录标识均保留。本次没有修改课程正文、评分、账号同步或实验算法。

## 验收

- 共享内容：13 项测试通过，完整导出 58 个项目、843 个节点，正文及作业与共享源逐字一致。
- 原生层：12 项测试通过，包括全部 58 张封面的实际解码、课程版本隔离、继续学习位置、SQLite 恢复和资源访问。
- 交互流程：首页与探索入口、连续选课及返回、项目介绍、进入课堂、笔记重启恢复、主题类型筛选及空结果恢复均通过；机械手和火星着陆的原有入口也通过回归。
- 布局：普通字号和辅助功能字号下，学习按钮无需滚动即可点击。横屏验收同时等待实际视口和截图完成旋转，避免把旋转中的画面当成最终布局。

复现失败结果：`build/catalog-regression-before.xcresult`。原生与首轮导航通过结果：`build/catalog-redesign-tests.xcresult`。最终目录与返回流程通过结果：`build/catalog-delivery.xcresult`。大字号通过结果：`build/catalog-layout-final.xcresult` 中的 `testCatalogAtAccessibilityTextSize`。横屏最终通过结果：`build/catalog-compact-final.xcresult`（使用 XCUIScreen 的完整设备截图，修复 XCTest 在旋转后裁切 App 窗口截图的问题）。完整内容导出与 App 包中的目录、封面逐文件核对一致。
