# 手机课堂交互修订

用户验收指出：长网页、分散的控制项和横向表格不适合手机。本轮将三个内置入口改为手机专用呈现，复用内容、模型、算法与记录格式。

## 布局约定

- 主界面占满可用窗口，模型、当前控制、下一步入口始终同屏。桌面查看器继续保留原有布局。
- 机械手：选择一根手指后只显示它的滑杆；姿态预设、结构开关和原理入口就在模型下方。详细计算分为角度、收绳、模型边界三个小页。
- 着陆：五个阶段直接可选，播放和时间轴固定在模型旁。阶段解释、思考题、部件目录按需打开，选择部件后回到模型。
- 阅读：按 Markdown 语法树拆成段落与列表项，保留原文。表格每一行转成一张字段卡片，不丢列、不缩小字体、不横向滚动；目录、资料、笔记从固定工具栏打开。
- 首页保留继续学习入口，三项内容直接展示，移除占据首屏的长宣传文案。
- 详细解释和大字号内容允许在当前卡片或弹层内纵向滚动；不能用裁切文字换取“无滚动”。主要操作按钮始终可见，触控目标至少 44 px。

## 状态与验证

保留原有活动 ID、关节参数、着陆时间、笔记；阅读位置新增稳定页 ID，旧记录仍可读取。验证 320 × 568、390 × 704（扣除原生导航后的可用区域）、横屏和 iPad 尺寸的主操作可见性、表格字段完整性、离线模型、笔记和页码恢复。通过模拟器端到端测试检查关键按钮不需整页滑动即可操作。

本轮仍是 App 内置的一个课文样例和两个实验，不代表完整平台课程均已适配；后续内容应遵循此布局约定逐类接入。

## 本轮验收结果 · 2026-11-17

- TypeScript 严格检查通过；6 项运行时测试通过，包括旧状态恢复、课程原文一致性、表格所有列保留、空单元格、转义竖线与 Markdown 链接。
- 5 种浏览器可用窗口尺寸通过：320 × 568、390 × 704、844 × 390、844 × 300、834 × 1000。机械手与着陆主操作均在屏内，未发生整页滚动和横向溢出；四种地形的三列内容全部保留。
- 320 与 390 宽竖屏、844 × 390 横屏及 iPad 尺寸下，当前 10 张阅读卡片均无需局部滚动。仅 300 px 高的紧凑横屏中，4 张较长卡片需要在卡片内纵向滚动，导航和笔记入口仍在屏内；没有裁掉正文。
- iPhone 18 Pro 模拟器、iOS 27.0：6 项原生测试与 3 项 UI 测试通过。验证首页全部入口、模型加载、横竖屏主要按钮可触达、公式面板、部件定位，以及终止 App 后恢复同一阅读页和笔记。最后调整首页顶对齐及阅读按钮标签后，又回归了两个相关 UI 流程。
- 原网站两个模型及 M01 Markdown 正文回归通过。网站保留原表格与原查看器；手机布局不加载网站的长页面组件。

本地完整测试报告：`build/mobile-redesign-final.xcresult`；最终首页与阅读回归：`build/mobile-redesign-delivery.xcresult`；浏览器尺寸报告：`build/mobile-check/report.json`。首次模拟器失败是测试把 WebKit 暴露为 Switch 的 `aria-pressed` 按钮按 Button 查询，改正查询后通过，未绕开部件操作。

仍待真机验收：软件键盘完整展开、VoiceOver、大字号、低内存、帧率与耗电。当前输入测试使用模拟器键盘环境，不代表这些真机项已经完成。iPad 目前只有浏览器尺寸验证，最低支持系统 iOS 17 也尚未实测。

### 后续内容接入要求

1. 先确定手机每屏的学习任务与主操作，再接入正文和实验；不能直接把桌面查看器作为完成适配的结果。
2. 复用活动标识、内容版本和实验计算，分别组织页面布局；正文标题可以提供手机显示名称，不能擅自删改原文或表格字段。
3. 每类新内容都检查：不滚动能否找到主操作、窄屏是否溢出、退出后能否恢复、详细内容是否仍有可到达的入口。
4. 正式课程仍须补齐讲课模式、学习记录、作业、实验产物和资料下载的原有语义，不能用浏览卡片数量判定学习合格。
