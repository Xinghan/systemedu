# SystemEdu iOS App

状态：方案草案，等待产品验收。创建日期：2026-11-17。本目录目前只有设计文档，尚未创建 Xcode 工程、复制资源或实现 App。

本方案按“整个 SystemEdu 学习平台的 iOS 客户端”设计。首批用一门完整课程和机械手、火星着陆两个实验验证体验，再扩展课程覆盖。

## 建议方案

采用 **SwiftUI 原生界面 + 本地 WKWebView 课堂组件 + 现有 SystemEdu 服务**。支持 iPhone 和 iPad，最低系统暂定 iOS / iPadOS 17；实施第一阶段确认设备范围。

- SwiftUI 负责课程浏览、继续学习、下载管理、账号、文件导入导出和系统导航。
- 课堂共用现有课文、公式、讲课模式和交互实验的渲染逻辑，打包为本地 Web 组件。Three.js 继续显示 Blender 导出的 GLB。
- 网站与 App 共用账号、课程标识、学习记录和后台服务；App 不直接连接数据库。
- 课程下载后可以离线阅读、操作已支持的实验、保存作业草稿。AI 导师、外部视频和需要服务端计算的任务联网使用。

课堂仍沿用正文中的富媒体入口和现有讲课方式；不把动画、游戏、幻灯片、作业拆成另一套学生课堂导航。

## 数据放在哪里

“保存在手机上”分为安装包、下载内容和用户记录，三者的更新与清理方式不同。

| 内容 | 共用来源 | App 中的位置 | 更新方式 |
| --- | --- | --- | --- |
| 账号、已加入的项目、正式提交、完成状态、学习路径 | 现有学生服务与数据库 | 保存当前账号需要的本地副本 | 登录及联网时同步 |
| 课程目录、正文、题目、讲义、公式、资源索引 | 同一份课程源文件与内容发布流程 | 按课程版本下载 | 内容发布后下载新版本 |
| Three.js 模型、图片、音频、教学资料 | 共用资源文件；手机需要时派生轻量版本 | 按需下载，明确选择“离线保存” | 随课程资源包更新 |
| 阅读器、公式渲染器、Three.js 引擎、已支持的实验控制逻辑 | 共用源码，分别构建网站和 App | **随 App 安装** | 随 App 版本更新 |
| 原生导航、图标、离线提示、基础演示 | iOS 专用界面；演示使用共用素材 | **随 App 安装** | 随 App 版本更新 |
| 答题草稿、实验参数、阅读位置、待同步操作 | 用户在设备上产生；可恢复部分同步账号 | 本地数据库，先保存再联网同步 | 每次学习操作 |
| 登录凭据 | 现有认证服务签发 | Keychain | 登录、失效或退出时更新 |
| 字号、主题、下载偏好 | 设备设置 | 本地偏好设置 | 用户修改时保存 |

安装包先内置两个小型实验及一节导览，使首次离线打开也能体验。两个现有 GLB 合计约 **6.66 MB**，连同原始预览图约 **9.94 MB**，尚未包含渲染引擎，不能视为最终 App 大小。Blender 源工程继续留在制作仓库；手机加载 GLB。完整课程视频、所有课程及模型不预装。

## 使用过程

1. 打开 App，在“学习”继续上次课程，在“探索”浏览项目，在“我的”管理下载和账号。
2. 进入课程后选择离线保存，看到资源大小和需要联网的部分。
3. 阅读课文，从原有入口展开公式解释、3D 实验和练习。实验全屏时适配横屏与触控。
4. 断网时继续学习，草稿和实验状态保存到手机；界面明确显示“已保存到本机”。
5. 恢复网络后同步到原账号。服务器确认后才显示“已同步”或“已提交”；跨设备冲突保留双方版本供核对。

网站上继续学习时，应能恢复相同活动的答案和实验产物。仅影响设备显示的相机角度、帧率等不计为正式学习成绩。

## 分阶段实施

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 1. 技术验证 | 原生容器、本地课文与公式、机械手和火星着陆 | 真机离线启动、触控、横竖屏、退出重进恢复、WebGL 生命周期 |
| 2. 一门课完整贯通 | 登录、项目目录、统一课堂、讲课模式、作业与资料下载 | 手机和网站使用同一课程版本与记录标识 |
| 3. 离线与同步 | 资源包下载、本地记录、同步队列、冲突处理 | 断网、杀进程、重复提交、账号切换、旧课程恢复 |
| 4. 覆盖与发布准备 | 扩充课程，接入在线服务，完成 iPad 和无障碍体验 | 实机性能、可恢复性、TestFlight 前检查 |

每阶段验收后再扩大范围。首次试用就验证真实课程流程，不以只有模型预览作为课程 App 完成的标准。
