# 用连续证据确认动作

confirm=3 表示连续三个有效读数都越过相应阈值，才改变状态。回到中间区间会清零连续计数，但不会改变当前开合状态。它与平均不同：平均改变数值，连续确认改变行动条件。

**算例：**采样周期 0.2 秒，第一次越过阈值时还不行动；第二次在 0.2 秒后，第三次在 0.4 秒后。相对第一次越阈时刻，多等了 0.4 秒；不能简单说确认 3 次必然延迟 0.6 秒。平均窗口也可能带来额外延迟。

在“短促信号”比较确认 1 与 3。若漏掉动作，要解释是窗口影响数值、连续确认积累不够，还是两者共同造成。

## 换一个角度检查

把输入写成 0.70、0.70、0.55、0.70：确认 3 次时始终不能闭合，因为中间的 0.55 打断了连续性。相反，滑动平均可能在这一串数据上超过阈值。先手推再看实验，说明你区分的是“数值处理”和“状态决策”两件事。
