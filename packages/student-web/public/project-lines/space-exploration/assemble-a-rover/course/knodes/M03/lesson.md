## 验收要包含“不顺利的时候”

只看正常输入，很容易漏掉异常。故障注入是有意让某一环节出问题，再观察系统是否按预期处理。本课提供相机丢失和电机停转，两者发生在不同层。

相机丢失时，第二段感知输出 unknown。正确的未知分支应停止，不能把它当成平地。电机停转时，规则仍可能发出正确命令，但执行反馈位移为零；这提示问题在动作执行，而非看路的标签。

### 一个最小验收矩阵

| 条件 | 期望观察 |
| --- | --- |
| 正常运行 | 抵达观察点 |
| 相机信息丢失 | 日志显示未知并停止 |
| 电机停转 | 命令与零位移一起出现 |

至少选择一种故障实际跑一次，再切回正常运行确认同一组合仍可到达。工作台会保留异常记录，验收把“异常时及时停下”视为有用证据，不要求每一条记录都是绿色。

**反例**：“重试成功了，所以不必保存失败。”删掉失败会失去说明改动依据的证据。真正的作品包包括模块来源、正常日志和故障日志。

交付前向别人解释：你是哪一层的制作者、失败来自哪一层、日志如何支持判断。这个组合可以带入远征课程，但还只是有限教学系统，不能下载到真实车辆直接运行。
