## 不只看“车到了没有”

一次运行日志应该能回答：场景是什么、识别器说什么、规则选择什么、车实际有没有移动。结果出错时，只有终点的成功或失败提示不够。

本课短途路线包含平地、软沙与岩石侧道。平台规则在平地前进、软沙慢行、岩石绕行，遇到未知停止。岩石侧道同时要求教学间隙至少 12 cm；即使规则正确，底盘不符合也会受阻。

### 同一个失败，可能有不同来源

软沙处打滑，可以先检查：场景确实是软沙吗？识别结果是否误成平地？规则收到 sand 后是否选择慢行？如果感知与规则都正确，再检查执行约束。

| 证据位置 | 要问的问题 |
| --- | --- |
| 感知 | 输入是否被误判或未知？ |
| 规则 | 给定标签是否映射到合适动作？ |
| 执行 | 命令发出后有没有位移？ |

自己的识别器可能不如平台预设标签可靠。这不是隐藏错误的理由。你可以保留这次失败，暂时选用平台识别器，同时仍使用自己的底盘或规则，形成贡献清楚的可运行组合。

**反例**：“车停了，所以代码坏了。”若输入 unknown，停止可能正是设计要求。要结合每一层的记录判断，而不是只盯着终点。
