## 档案要能讲清一条证据链

从已有实物车开始，你提出观察目标，比较两版预算，量出真实场地，再用至少两次任务尝试完成调整。最终档案应该让别人看出每个决定根据什么，而不是只看见一张好看的车照片。

上传两张本次远征现场照片：一张能看到路线与标尺，另一张显示观察点或带回的观察结果。写清对应哪个版本和哪次尝试。不要重复用制造课的照片冒充新任务；示意图、模型截图和 AI 生成图片也不算现场证据。照片只需作品和场地，不需要孩子入镜。

## 三句话足够，但要具体

第一句解释任务取舍，例如为什么绕路、缩短任务或增加预留。第二句引用两次现场数据，说明调整产生的影响。第三句说明模型没有预测到什么，或哪些部分由平台、成人和孩子分别完成。没有自动相机时，明确观察照片是孩子在车辆停稳后拍摄的。

平台核对材料是否齐备、数字日志是否与参数对应、数值是否满足基础格式。它无法仅靠填写内容确认真实设备成功，也不会自动宣布掌握。提交后是待评阅状态；你可以返回查看已交付版本或导出完整证据包。

## 带着问题进入完整工程

接下来真正值得升级的可能是位置反馈、自动图像采集、更多地形或远程通信。把这次遇到的一个真实限制作为下一课的问题。原始数据和制作经验可以继续用，不能凭小车交付跳过完整火星车课程自己的验证要求。
