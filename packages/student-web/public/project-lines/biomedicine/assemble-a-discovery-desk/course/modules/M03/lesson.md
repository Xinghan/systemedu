## 今天收到一个异常批次
上游服务完成批处理后，候选数量看起来正常。可是你不能据此保证预测对应正确。运行异常批次，先看现象，写一个可以被检查推翻的猜想，再选择检查工具。

本课提供三类证据：两张表开头的 ID 顺序、字段单位、是否有缺失。检查没有发现问题也有价值，它能排除一个解释。至少使用两项检查，让自己的判断建立在证据组合上，而不是碰巧猜中某个选项。

## 两种关联方式
按行号交接假定两个服务永远返回相同顺序。按 ID 交接则明确寻找属于同一分子的结果。哪一种适合这里，要由你刚才采集的证据支持。改变关联策略以后，再运行同一异常批次，查看逐行关联是否恢复一致。

## 修好了哪里，没修好哪里
关联修复可以让预测属于正确分子，但不会让预测本身自动更准。如果当前方法本来误差就大，修复后仍可能很大。这正是系统检查和模型评估的区别。请不要用“所有点回到对角线”作为修复目标。

写下原假设、两项观察、采取的修复、以及复测结果。平台提供故障环境和检查工具；解释证据之间的关系由你完成。
