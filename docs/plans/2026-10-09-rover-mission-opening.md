# 火星车任务开场实施计划

**Goal:** 在实验分支制作可用手机验收的第一人称火星车任务开场，以生成场景图片、动态观察和真实可操作的路线判断带入现有课程。

**Architecture:** 独立 `/mission/rover` 原型入口，复用现有 Next.js 与学习记录接口。场景通过生成图片、视差、扫描、路径动画及确定性的教学状态机驱动，不宣称是原生 iOS 或真实火星直播。完成开场后进入原有课堂，不新增动画/游戏分类 tabs。

**Tech Stack:** React、TypeScript、CSS motion、生成式场景图、现有 LearningRecordSession、Playwright。

## 体验

1. 学生坐进地球控制席；虚构的中国工程师“林岚”面对学生说话，以中文配音、对白字幕和学生的回应讲述“晨光号”任务。第二个镜头中她指向屏幕，带学生进入火星车相机。采用电影式图片分镜及镜头运动，不声称是口型驱动视频。任务是到层状岩石观察点回传一张照片。
2. 打开前视相机，检查岩石、松软沙地与目标岩层三个热点，留下观察标记。
3. 对比两条教学模拟路线：短路穿越软沙触发保护停车；绕行硬地可到达但消耗更高。学生选择后才显示执行结果，失败可保留记录并重试。
4. 自动执行计划：路线和步骤同步推进，支持暂停/继续；切到后台暂停，不假装即时遥控真实火星车。
5. 抵达后由学生完成取景确认，生成包含路线、观察与尝试的任务档案。
6. 将后续课程呈现为真实任务模块：识别地形、编写规则、制造探测车。链接进入既有课程，开场不算完成正式课程。

## 实施文件

- 新建 `packages/student-web/src/components/mission/rover-opening.tsx` 和 `.module.css`：控制席、相机、热点、规划、执行、取景、成果。
- 新建 `packages/student-web/src/lib/rover-opening.ts`：版本化作品格式、路线规则、输入校验；与实际漫游车物理模型区分。
- 新建 `packages/student-web/public/mission/rover/`：三幅生成场景及响应式 WebP，图片内无文字，UI 单独渲染。
- 新建 `artifacts/rover-opening-20261009/`：提示词、素材说明、浏览器验收与截图。

## 保存及异常

开场独立 activity ID，不改变旧课 module ID、版本或完成状态。游客本地保存；登录用户使用现有记录服务，失败如实显示并支持重试。不自动覆盖服务端冲突。动画进度不频繁写库，只保存有意义的选择与完成步骤。图片加载失败可重试，文字和操作可继续；静音默认，音效由显式操作启用；支持减少动态效果。

## 验收

- 手机 390/320 宽、桌面、短横屏布局，无遮挡和横向溢出，热点点击目标至少 44px。
- 完整体验：接任务、观察、选路线、失败停车、改线、成功取景、成果与课程入口。
- 重新打开后恢复作品；声音、暂停、跳过开场、减少动态效果可用；卸载不遗留音频或计时器。
- 单独验证路线和作品校验；浏览器检查实际生成图已加载、无运行错误。
- 检查自身 lint/类型诊断，不将已有 6 个 TypeScript 错误误报为本批通过。
- 只提交本批明确文件，commit、push 并核实远程。用户未要求部署生产。
