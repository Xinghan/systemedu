# M90 Workbench Teaching Slides Implementation Plan

**Goal:** Apply the updated course-slide-visuals decision cards, then replace the 10 M90 teaching slides with a source-aligned, inspectable software assembly and evidence-report demonstration. Preview only; no production deployment.

**Architecture:** A typed `workbench-evidence` renderer has ten teaching scenes. Pure functions own feature contracts, stub inference, filtering/ranking, evaluation auditing and report assembly. RDKit provides actual structures/descriptors. Model predictions and metric examples are explicitly fabricated teaching records, not trained-model results. All 10 source IDs and anchors are retained in a versioned draft, with new narration but no stale audio.

**Tech Stack:** Existing React/Next, RDKit.js, KaTeX, DOM/CSS and the single-slide carousel; no new dependency. Existing project color tokens. This software capstone does not benefit from a generated physical-workbench image or a 3D machine.

- Separate interface run status, policy recommendation, and real-evidence availability. Missing model/assessment data must not be replaced with zero or claimed as a Go.

- Output: report JSON with all inputs, sources, rule thresholds, ranking, limits, missing real-model evidence and teaching-only status. Top10 is a maximum; never pad three candidates to ten.
- Test: independent RDKit recomputation, contract failures, pipeline stop position, ties, filtering, AUC pair counts/MAE arithmetic, leakage/missing evidence, report provenance.
