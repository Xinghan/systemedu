# 恒星亮度观测：初中零基础学习路径审计

状态：现有 iPad 内容审计与重构设计草案。不是新版课程的发布记录；没有修改正式课文、节点、记录或 App。

## 结论

当前材料不宜宣称「初中零基础学生可独立学会」。这是对内容顺序、隐含前置能力和实际操作要求的审读判断，不是已经进行学生试教后的实验结论。用户本人完整阅读时无法跟随，是需要正面处理的可用性反馈。

问题不等于「总字数太多」或「缺少卡通图片」。当前课程强调研究过程、证据完整和复现，但将很多刚接触天文、图表和编程的学生尚未学会的能力当作起点；以术语解释、操作指令、概念弹层代替了逐步建立理解。内容可以是进一步开发的资料底稿，不能据其文件齐全、媒体可点击、自动检查通过就宣布教学可用。

## 应采用的主线

受众：初中生，不预设天文、统计或编程基础；不假定所有人已熟练掌握坐标图、百分数和文件管理。暂不规定总节数和总学时，按真实前置关系拆分，试教后再定节奏。最终保留真实数据研究与复现要求；前置学习可以增加，不能靠降低科学目标掩盖断点。

先走一条连续路线：

1. **弄清我们在看什么。** 太阳、恒星、行星、望远镜和观察者的位置。成果是一张由学生标注的观察关系图。
2. **把收到的光记录下来。** 用明确标注的模拟灯光，先只比较两次读数，理解「一次测量」。成果是三条带时间的记录。
3. **亲手把表变成图。** 教师示范一个点、学生完成一个、独立完成另一组。先不用天文时间基准。成果是一张能指认横纵坐标的小图。
4. **解释暂时变暗的一种可能。** 先固定视角，只移动遮挡物；同步展示光路、观测画面、读数与图点。成果是遮挡前／中／后的记录及自己的解释。
5. **理解为什么有行星也未必看得到遮挡。** 只改变观察方向，保留其余条件；先预测、后操作、再对照。成果是两个视角的对照图。
6. **学会承认不知道。** 明确区分亮度低、读数为零、没有测量。先在五条构造记录上练习，再看真实资料。成果是正确标注的缺测图。
7. **第一次接触真实星光记录。** 用选出的原始数据小片段逐点连接「真实望远镜—测量—表—图」，说明与教学模型差异。成果是自己解释的一处变化，不要求此时自主排除全部可能原因。
8. **提出一个有依据的小问题。** 先完整示范一个观察怎样变成问题，再换位置让学生独立完成。成果是初版观察卡；替代解释和反证标准随后通过具体实例逐步补全。

每一段都需要「背景与目的 → 一个可见现象 → 明确讲解 → 完整示范 → 带提示操作 → 换例独立操作 → 解释与反馈 → 保存有意义的结果」。这描述的是认知递进，不是强制塞八个版块或八个 tabs。

背景要就地教，不能让首次使用者为了理解当前页面跳转到资料库。专业术语保留，但在学生已有可指认的对象和动作后命名。学生做错时，反馈要指出误解在哪，并回到相关观察；不能只显示参考答案或要求「再想想」。

## 先验证什么，才值得继续批量生成

优先制作和试教「收到的光—三条记录—自己画点—遮挡导致变化」的一段完整学习体验。先用真实 iPad 上能直接执行的操作完成闭环，再扩展到整门课。

检查学生能否在作者不解释的情况下：说清当前目标；找到需要观察的位置；解释一个点的横纵坐标；在新例子中分清缺测和亮度变低；用自己的话解释一次遮挡；保存并找回自己的结果。记录卡住的位置、求助内容、错误判断及提示后的变化。不把阅读完成、答题点击或作品文件存在当作理解证据。

设备限制需要正面解决：当前课文中的桌面终端和本地 Python 流程不是 iPad 操作流程。后续选择真正可执行的 iPad 运算方案并验收前，不可承诺学生全程在 iPad 上完成原始 Notebook 路线。云端运算尚未接入，不能以假按钮或预先算好的输出冒充学生运算。

本次尚未进行学生试教，也未生成/替换正式新课；不宣称通过 course_factory 的完整课程与媒体验收。审计依据现有 `course_factory/SKILL.md` 的「缺失前置知识要铺成节点」以及 `references/chinese-teaching-language.md` 的就地材料、完整示范和学生视角验收要求。
