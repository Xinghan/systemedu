# SystemEdu iOS App Implementation Plan

> 按阶段逐项实施，每批先检查和验收，再提交、推送。当前只交付设计，后续实施以用户确认的范围为准。

**Goal:** 在独立目录建立 SystemEdu iOS 客户端，共用课程和账号记录，支持本地课堂与下载后的离线学习。

**Architecture:** SwiftUI 管理导航、认证、下载及本地保存；抽取现有课堂为本地 WKWebView 组件。网站与 App 使用相同学生服务、课程发布来源和活动标识，补充不可变课程发布物和移动同步适配。

**Tech Stack:** SwiftUI、WebKit、URLSession、SQLite3、Keychain；共享 TypeScript / React / Three.js / KaTeX；现有 Python 学生服务与内容服务。暂定最低 iOS / iPadOS 17。

**Status:** Proposed，2026-11-17。未创建 Xcode 工程，未执行以下构建和验收命令。

## 阶段 1：先验证原生课堂与两个实验

### Task 1：定义契约和迁移样本

**计划新增：**

- `packages/learning-contracts/schemas/course-release.schema.json`
- `packages/learning-contracts/schemas/learning-host.schema.json`
- `packages/learning-contracts/fixtures/` 下固定课程与学习记录样本
- `packages/ios-app/docs/content-compatibility.md`

**步骤：**

1. 选择一门已发布、能覆盖正文、公式、讲课模式、实验和作业的课程；记录 slug、module_id、activity_id、content_version、编号协议及资源来源。
2. 以现有 manifest 为基础定义 release 和能力字段；将 guided-course 本地内容、library 内容、独立实验分别列出适配状态。
3. 把真实脱敏样本固定为契约 fixture，明确“完成 / 提交 / 评分”不同语义与 256 KB 请求上限。
4. 定义课堂宿主接口和状态版本，不重命名历史记录标识。
5. 检查样本能对应现有网页，记录缺失资源和未适配活动。提交 `docs(ios): define content and learning contracts`。

**验收：** 两端可用同一 fixture 解释同一活动；没有把当前 latest 当作可取回的历史版本。

### Task 2：抽取最小共享课堂运行组件

**计划新增：** `packages/learning-runtime/package.json`、`src/host.ts`、`src/entry.tsx`、`src/experiments/`、`scripts/build.mjs`、`tests/host-contract.test.ts`。

**计划修改：**

**步骤：**

1. 梳理 Next 路由、字体、绝对资源 URL 和浏览器 API 依赖，先抽出资源解析、实验状态与生命周期。
2. 定义 Web host 与 iOS host，课堂通过统一接口读资源、保存状态，不自行取得账号 token。
3. 抽取两个实验的共同源码，网站原入口继续消费相同实现；不复制后各自修改。
4. 建立独立静态构建输出，锁定依赖，检查运行时不请求 CDN 脚本。KaTeX 字体、GLB 解码器跟随构建产物。
5. 验证原网页实验仍可操作、恢复状态；确认新构建不依赖 Node 文件系统和 Next 服务端。

**拟定检查命令（新增脚本后可用）：**

```sh

npm --prefix packages/learning-runtime test
npm --prefix packages/student-web run build
```

预期共享构建和契约检查成功，现有网站构建无新增错误；网站启用了忽略 TypeScript 构建错误，不能把 next build 成功作为新增共享包类型正确的证据，共享包需独立严格检查。通过后提交 `refactor(learning): share classroom runtime with iOS`。

**步骤：**

## 阶段 3：离线下载与可靠同步

### Task 6：资源包下载与本地记录

**计划新增：**

- `packages/ios-app/SystemEdu/Services/{DownloadManager.swift,ContentPackInstaller.swift,SyncCoordinator.swift}`
- `packages/ios-app/SystemEdu/Persistence/{LearningStore.swift,OutboxStore.swift,MigrationRunner.swift}`
- `packages/ios-app/SystemEdu/Features/Downloads/DownloadsView.swift`
- `packages/ios-app/Tests/{ContentPackTests.swift,LearningStoreTests.swift,SyncCoordinatorTests.swift}`

**可能修改：** `packages/student-app/src/systemedu/student/catalog/{routes.py,user_lit_routes.py,user_lit.py}`，为离线完成状态与位置补并发保护；相应扩展 `tests/student/test_progress.py`、`test_user_knode_complete.py`。

**步骤：**

1. 完成 SQLite 表与账号分区迁移，草稿和 outbox 同事务写入；测试写入后杀进程仍可恢复。
2. 实现下载大小预览、空间检查、中断恢复、校验、原子安装与旧包保留。
3. 复用 revision、request_id 实现草稿同步和提交；明确提交快照与后续编辑顺序。
4. 实现冲突核对和当前账号检查；401、超时、5xx、离线均保留可恢复内容。
5. 保持“清下载 / 清缓存 / 退出项目 / 退出账号”操作语义分开；不因清理资源删除草稿。
6. 核对备份排除范围、旧包依赖、导入文件与本地存储保护；同一账号再登录恢复待同步记录。

**必须完成的故障验收：**

| 场景 | 预期 |
| --- | --- |
| 下载中断、文件哈希错误、磁盘不足 | 不安装半包，原有可用版本继续工作。 |
| 断网填写答案后杀进程 | 再启动恢复本机答案与实验状态。 |
| 服务器已提交但客户端超时 | 同 request_id 重试只有一份提交。 |
| 网站和手机同时改同一草稿 | 返回版本冲突，双方内容都保留。 |
| 账号 A 排队后切换 B | A 请求不会使用 B 凭据，B 不显示 A 草稿。 |
| A 版本学习中发布 B 版本 | 不混用内容，旧记录仍能关联 A。 |
| 删除课程下载后重新下载 | 学习记录保留，资源按固定版本恢复。 |
| 完成状态重试或跨设备撤销 | 不使用 toggle 重试，不默默反转最新状态。 |

通过后提交 `feat(ios): add offline downloads and record sync`；按改动范围运行 iOS 单元/UI 测试与学生服务对应回归。

## 阶段 4：课程覆盖与发布准备

### Task 7：扩充内容、在线能力与设备体验

**计划修改：** `packages/ios-app/docs/content-compatibility.md`、共享课堂组件、iOS Features 及对应测试。

1. 按兼容性清单扩充课程，逐项适配 JSXGraph、RDKit、较复杂公式和较大场景；需要新增执行能力时发新版 App。
2. 接入已有 AI 会话协议，明确联网状态；本次尚未确认通用代码执行 API，不把在线 Python 运行列为现成能力。代码练习先支持编辑与保存，再单独评估运行服务。
3. 如试点需要图片/PDF 作业，再设计附件存储、归属校验、上传重试和记录引用；不突破当前 JSON 接口上限。
4. 完成 iPad 布局、VoiceOver、大字号、Reduced Motion、触控与横屏；3D 关键概念提供文字和参数控件。
5. 记录包体、帧率、内存、耗电、网络错误率和恢复成功率；先观察数据再引入更复杂资源分发机制。

提交 `feat(ios): expand supported learning activities`，每批附兼容清单与实测记录。
