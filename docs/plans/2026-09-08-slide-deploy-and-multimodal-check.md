# Slide deployment and multimodal validation Implementation Plan

**Goal:** 发布用户已确认的分子猎人 M81，随后选取一个具有实物/空间/定量内容的节点，依据 course-slide-visuals 制作多模态教学样例并供用户预览。

**Architecture:** 以生产源码和课程为基线做白名单增量发布，避免把本地其他未发布工作带入生产。新样例复用实际 SlideBody 和现有 KaTeX/Three.js 等依赖，图片独立生成压缩，所有产物建立页码映射。

**Tech Stack:** Next.js / React、KaTeX、JSXGraph、Three.js、现有 DashScope TTS、既有课程 import/publish 流程。

## Task 1 — M81 发布前内容与音频一致性

- 检查 M81 slides、课文、理论、活动和作业里的冲突；保留原始文件备份，统一教学数据与结论边界。
- 使用现有配置的语音合成流程生成新版讲稿音频，版本化路径不覆盖旧音频；检验 WAV 和时长，再更新 slide 映射。
- 输出：M81 可发布增量及音频；运行 13 项现有相关回归测试和内容一致性检查。

## Task 2 — 隔离生产发布

- 依据 scripts/deploy.env 登录，仅检查服务状态，不输出秘密。
- 从当前线上 student-web 源码暂存，仅覆盖 slide 渲染所需白名单文件；不复制首页、后台、开发预览路由。
- 正式构建，4001 回环冒烟检查，再切换前端；留旧目录、旧静态块和自动回滚。
- 课程从线上目录复制，只覆盖 M81 目标文件；验证 manifest、备份内容与 SQLite，按既有 import/publish 单课程上架。
- 验证健康、发布版本、M81 接口 11 页/媒体哈希，以及非目标节点未改变；打开线上节点检查实际渲染。

## Task 3 — 选择新节点并应用完整工具箱

- 读取实物项目候选节点，选择原文确实同时包含实体/空间关系和定量知识的一个节点。
- 对每页记录教学目标、对象、关系、最合适媒介、最接近的替代方案为何较弱；区分示意、模型计算与真实测量。
- 生成知识承载型浅色位图；使用可检查程序化几何制作互动 3D；公式、图表与数据使用确定性 HTML。
- 保存原文、产物和映射记录，新节点先本地预览，不自动部署。

## Task 4 — 验证与 skill 审查

- 检查数值边界、几何关系、动画重置/停止、WebGL fallback、移动布局和浏览器错误。
- 在真实 slide 组件打开新样例，标记图片、互动 3D、公式、模拟的具体页码。
- 对照实际路由审查 skill 是否抑制合理图片/3D、是否混淆渲染与模型、是否诱导无依据的多模态配额；有必要时提出或实施范围内修正，记录变化。

不提交全部脏工作区、不执行 deploy all、不覆盖其他课程。当前请求已明确授权执行，不另起任务或派生代理。

## 执行结果

- Task 1/2：M81 内容统一并完成 scoped deploy。TTS 外发被权限审核拒绝，已向用户解释并等待明确授权；发布为明确无配音版，不复用旧音频。健康、API、文件范围校验通过；生产浏览器打开超时，无登录态截图。
- Task 3：选择 emg-prosthetic-hand / M42；完成 12 页待审核草稿，含 44,508 字节生成 WebP、实际 Three.js 装配/力臂模型、KaTeX、可记录解析实验和 PNG 产出。
- Task 4：实际 SlideBody 逐页检查与关键交互通过；7 项自动测试、相关 ESLint 通过。skill 审查记录于 M42 visual brief，未修改全局 skill；未部署新样例。
