# iPad Simulator 的照片导入与 Mac 拍摄

本批次解决两件事：向明确指定的模拟器导入单张 Mac 图片，以及让 Debug 模拟器使用 Mac 摄像头取景。目标设备为用户确认的 iPad Air 11-inch (M4)，UDID `514BC1A2-E3D6-47CE-B4C6-823459A82BEB`。

## 照片导入

Mac Photos 图库与 Simulator Photos 图库分离。本机同时启动了 iPad Air 与 iPad Pro，原指引没有明确目标设备，拖拽方式也未在当前 Device Hub 验证。改为从 Mac Photos 导出图片文件，通过 `simctl addmedia <UDID> <file>` 导入，再重新打开 App 照片选择器。

新增导入脚本列出已启动设备；多设备时必须提供 UDID，不会静默选择设备。以仓库原创卡通角色为样本，验收覆盖「导入 → 相册出现 → 点选 → 原照预览 → 显示生成按钮」，不触发真实供应商调用。

## 摄像头路径

真实 iPad 使用原生 UIImagePickerController。Debug Simulator 使用 MacCameraView：本机服务通过默认浏览器请求 Mac 摄像头，浏览器获得用户授权后发送低频 JPEG 到 loopback，模拟器轮询并展示。学生在模拟器点击拍照，走既有图片规范化与预览流程。生成和确认形象仍是后续明确操作，保持既有单线学习流程。

未选择依赖原生模拟器相机透传：当前实际运行只得到灰色画面。未选择原生 macOS 助手：它会增加独立签名、安装与分发步骤；浏览器能复用已具备的相机授权机制，适合本机开发试用。

## 数据与失败处理

- 读取与写入凭据分离；浏览器凭据只在 fragment 传入，加载后从地址栏移除，不记录请求日志。
- 服务只监听 127.0.0.1，检查 Host/Origin，固定资源白名单和严格 CSP；不采集音频。
- 只在内存保存最新 JPEG，重编码清除元数据。取消、拍照、超时与退出销毁连接；异步晚到帧不能恢复已删除会话。
- 权限拒绝、摄像头占用、服务未运行、连接过期分别提示。取消保留名字、角色与已有照片预览。
- 不引入生产后端或部署；现有头像服务的供应商、输入说明与 Release 限制保持一致。

## 验证范围

Python 测试覆盖读写隔离、输入校验、跨站拒绝、过期与清理。浏览器使用合成视频测试真实 getUserMedia 与 HTTP 链路，并模拟权限拒绝。iPad Air UI 测试验证取景、拍照、取消、服务不可用、原生权限分支与相册选图。只使用合成图像；真实 Mac 摄像头需要用户授权后进一步检查。结果记录在 `artifacts/space-expedition-20261126/camera-verification.json`。
