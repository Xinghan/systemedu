# iPad Mars Learning Implementation Plan

> Execution: implement the following tasks in this session, using the existing working branch and preserving unrelated edits.

**Goal:** Make the complete existing Mars exploration journey usable in an iPad simulator, with home, eight-station map, films, lessons, lecture mode, activities, downloads and durable local records.

**Architecture:** Keep SwiftUI navigation and SQLite storage; add a tablet mission shell backed by a validated export of the existing mission configuration. Adapt the shared classroom to iPad width with section navigation and a concurrent notes/resources inspector. Keep phone views, source lessons, IDs, versions and all original content available. No App Store or TestFlight distribution in this batch (confirmed by user).

**Tech Stack:** SwiftUI, AVKit, WKWebView, React/TypeScript, existing JSON/Markdown curriculum, XCTest and Playwright.

## Design and scope

Selected approach: native iPad home/map/library with the existing local classroom. A full remote website wrapper would lose reliable offline records; rewriting every lesson and experiment in Swift would duplicate existing science and content. Reuse authored media and simulation logic, redesign their navigation and available space.

The first featured project is the existing 火星地形观察远征: eight task stations, all 85 mapped source nodes, three micro activities, optional transit research and retained older editions. Existing source hardware/navigation gaps remain visible; this UI release does not establish physical engineering validation. All other catalog courses remain accessible in the resource library, with no deletion.

Use an unoccupied research-room background on home, the existing campus map with eight touch targets, and the existing continuous character videos for briefings. Landscape keeps mission navigation and content side by side; portrait reduces navigation and moves station details beneath the map. Lessons use section-length reading and real tables; notes and references can remain open beside the lesson. Activities and lecture mode get a large, dismissible surface.

## Task 1 — Export and audit the journey

- Create `packages/learning-runtime/scripts/ipad_mission.py`; invoke it in `export-content.py` after catalog assembly.
- Resolve every mission reference against the exported catalog, preserve IDs/versions and classify lesson/support/optional/replaced content. Fail on missing nodes or required media.
- Export home/map assets, actual films/captions, station steps, original project lists and existing bridge limitations.
- Add `packages/learning-runtime/tests/ipad-mission.test.mjs` for full coverage, source identity and local media.
- Save a per-node destination inventory under `artifacts/ipad-mars/`.

## Task 2 — Native iPad shell

- Add `SystemEdu/App/TabletMission.swift` and `SystemEdu/Features/TabletMissionView.swift`.
- Switch `RootView` to the tablet shell on iPad. Feature a single Mars journey; keep the complete catalog as a secondary entry.
- Add home, interactive map, station lessons, films with captions/transcript, local progress and links back to all original courses. Never infer completion from a visit or film playback.
- Use the existing activity records for resume/export; a separate local mission note stores trial feedback without overwriting coursework.
- Regenerate the Xcode project with `scripts/generate-project.py`.

## Task 3 — iPad classroom

- Pass an explicit tablet presentation flag from `LearningWebView` to the runtime entry.
- Adapt `CourseReader`, `Sheet` and styles: persistent section outline, longer reading sections, full tables, docked notes/resources, large lecture and experiment panels.
- Keep existing reading IDs, workspaces, question keys and lecture indices readable. Existing source download and media links remain available.
- Include previous/next mission steps and a direct route back to the map in native navigation.

## Task 4 — Verify and deliver

- Run typecheck, runtime tests and browser checks at tablet landscape/portrait sizes. Verify notes alongside reading, activities, tables, lecture, resources and save/reload.
- Build and run on an available iPad simulator. Exercise home → film → map → lesson → activity → note → relaunch/resume; inspect landscape and portrait screenshots.
- Verify bundled media and per-node inventory; report external resources requiring network and existing course gaps honestly.
- Update iOS README and an iPad trial guide. Commit and push each reviewable batch to the current branch, checking the remote hash. Do not deploy the website or publish to an app store.
