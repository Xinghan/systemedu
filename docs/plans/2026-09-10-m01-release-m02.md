# M01 发布与 M02 续作计划

**Goal:** 定向发布已审阅的 M01 八页，再制作 M02 本地预览。

**Architecture:** 沿用逐 step 发布。前端只新增 M01 renderer、模型、CSS、图片与两处分派；课程只更新 M01 六个配套文件。先验证生产基线，再构建、烟测、切换、课程发布、API/hash 验证。新 M02 不进入本次生产包。

**Tech Stack:** Next.js、现有 RDKit/KaTeX、Python 课程导入与 manifest 校验。

1. 检查生产构建、依赖、磁盘；保留旧前端与课程回滚备份，只清理已验证的重复临时副本。
2. 冻结 M01 已审阅 draft hash、原始 source hash、发布文件白名单。复用已安装的相同依赖；课程使用写入前解链的硬链接副本节省磁盘。
3. upload → stage → build → smoke → stage-course → audit-package → switch → publish-course → verify；每步独立调用并看结果。
4. HTTPS 图片 hash、项目路由、服务健康；成功后同步本地 canonical 六文件、manifest、registry、进度和发布记录。新讲稿无音频，解绑旧音频。
5. 阅读 M02 全部 source；在设计记录里逐页对比图片、3D、精确结构、动态执行与实验手段。软件安装不能用假成功日志或浏览器 RDKit 冒充 Python 环境验证。
6. 制作八页，保留 slide ID/anchor；测试状态转换与实际库输出、尺寸/浮窗、错误和降级；提供直接预览。

用户已批准部署并继续，无需反复确认步骤。不提交无关工作区修改，不新建子任务或擅自全量部署。
