# 分子怪物猎人 · M05 / M23–M28 技术视觉波次记录

> 本波次不生成装饰性图片。内容的学习目标是“读懂 SMILES、定位报错、执行列表与循环、得到可复核的输出”，因此使用 RDKit.js 的确定性二维结构和可交互的代码状态轨迹。这样学生看到的是输入、运行状态、变量与输出之间的因果链，而不是没有信息量的氛围图。

- 课程项目：`molecule-monster-hunter`
- 节点：`M05-w0-module`、`M23-w0-pubchem-smiles`、`M24-w0-smiles`、`M25-w0-module`、`M26-w0-module`、`M27-w0-rdkit-smiles`、`M28-w0-canonical-smiles`
- 实现：`payload.technical_visual`；原有 `inline_svg` 仍保留在源数据中作回退，但有技术视觉时不同时呈现。

## 动态策略

- 每个 `code-trace` 都有至少三段可由学生点击推进的程序状态，不使用装饰性的脉冲、循环箭头或淡入。
- 每一状态同步更新：高亮的代码行、变量面板和终端输出；这三个变化共同说明“哪一行代码导致了什么结果”。
- 分子结构页不做伪 3D 动画：二维骨架、原子高亮和 SMILES 已足以支撑本页目标。若后续某页确实讨论构象、朝向或结合口袋，才按 skill 的 3D 准入门槛使用可检查的三维模型。

## 精确性边界

- 化学结构由随学生端发布的本地 `@rdkit/rdkit` WebAssembly 渲染，不依赖 CDN，也不把原子、键、SMILES 或标签交给图像模型生成。
- 代码文本、变量和输出均是页面 DOM 中的固定课程数据；不执行学生输入或任意脚本。
- 本波次未映射任何栅格图，因此没有为“有图”而牺牲公式、结构和程序状态的准确性。

## 质量检查

- 结构、SMILES、列表、索引、循环、异常收集和规范化均可追溯到对应节点的原始讲稿。
