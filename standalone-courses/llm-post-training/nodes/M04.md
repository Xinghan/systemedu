## 01 · QLoRA：存储精度和计算精度分开看

QLoRA 的核心是冻结量化后的基座权重，同时训练较高精度的 LoRA 适配器。需要矩阵运算时按实现使用反量化后的值参与计算，梯度传到适配器；4bit 不是“整个训练都在4bit中进行”。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

论文中的关键组成包括 NF4、double quantization 和 paged optimizers。NF4 面向近似正态的权重分布构造非均匀量化表示；它不是普通均匀 INT4，也不是4位浮点算术计算格式。double quant 进一步压缩量化常数；paged optimizer 处理显存峰值，不等于模型权重可以无限放进 GPU。

本项目实现 **NF4 基座 + double quant + LoRA + 普通 AdamW**。没有自动启用 paged optimizer，也不宣称复现论文的全部优化。这样可以直接沿用上一节点的优化器与检查逻辑。

## 02 · 按正确顺序准备模型

```python
compute_dtype = (torch.bfloat16 if torch.cuda.is_bf16_supported()
                 else torch.float16)
quant = BitsAndBytesConfig(

```

先准备量化基座，再注入 adapter，避免后续冻结操作把刚加入的可训练权重一起冻结。检查可训练参数和实际 dtype，不要根据变量名假定所有 adapter 都是 BF16：PEFT 可能为稳定性保留或提升适配器精度。[PEFT 量化训练指南](https://huggingface.co/docs/peft/v0.18.0/developer_guides/quantization)

本实现单 GPU 固定 `device_map={"": 0}`，不使用推理场景常见的自动跨设备分配作为训练方案。若改成多卡/FSDP，需要重新设计加载、分片与优化器路径，不能仅改一个 device_map。[Transformers bitsandbytes 文档](https://huggingface.co/docs/transformers/v4.57.3/en/quantization/bitsandbytes)

## 03 · 做显存账本，不做“4bit等于四分之一”的推断

近似分解训练峰值：

$$M\approx M_{base}+M_{adapter}+M_{grad}+M_{optimizer}+M_{activation}+M_{workspace}.$$

理想化的 P 个4bit权重占 $P/2$ 字节，但实际还有分组量化常数、未量化层、对齐和临时缓冲区。LoRA 只减少可训练参数对应的梯度/优化器状态；QLoRA 额外压缩基座存储。长序列或大 microbatch 下，激活仍可能主导峰值。

```python
torch.cuda.reset_peak_memory_stats()
# 至少经过一次完整 forward/backward/optimizer.step 后再读
allocated = torch.cuda.max_memory_allocated() / 2**30
reserved = torch.cuda.max_memory_reserved() / 2**30
print({"allocated_GiB": allocated, "reserved_GiB": reserved})
```

allocated 是张量分配峰值，reserved 是缓存分配器保留峰值；它们都不保证等于 nvidia-smi 看到的进程占用。首次优化器 step 才可能创建 Adam 状态，因此只测模型加载后的数字会漏算训练成本。

## 04 · OOM 的排查顺序

先记录失败发生在加载、前向、反向还是更新。加载时失败，检查模型大小、量化是否真正生效和设备放置；前向/反向失败，先降低 microbatch 与 max_length，开启 gradient checkpointing；更新时失败，检查 trainable 集合和 optimizer 状态。降低累积步数通常不会降低单个 microbatch 的激活峰值。

Gradient checkpointing 通过重算部分前向换显存，不能免费加速。把开启/关闭时的步耗时与峰值放在一起比较。对本项目的0.5B模型，QLoRA未必比普通 LoRA 更快；反量化开销、小矩阵效率和设备共同影响吞吐，应测量而非预设结论。

## 05 · 公平比较需要四组结果

运行未适配的高精度基线、未适配的 NF4 基线、LoRA、QLoRA。只比较 LoRA 与 QLoRA 会把量化对初始模型的影响和训练影响混在一起。四组使用同一模型 SHA、测试集 hash、prompt、输出上限和确定性解码。

**节点作业 D · 显存与效果实验。** 在同一张 GPU 上固定 r、alpha、数据与步数，运行两种训练配置；补充 NF4 基线。提交四组 schema valid / exact match / macro F1 与逐例结果，训练 allocated/reserved 峰值、耗时、GPU型号、软件版本。至少解释一个内存账本无法精确预测的实测差异。没有 GPU 时可先写实验协议并通过 CPU 测试，但该节点的训练验收保持未完成。
