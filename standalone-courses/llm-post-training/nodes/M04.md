## 01 · 三种精度与两条计算分支

学习 QLoRA 前先确认 M03 的结论：LoRA 保留基座权重，同时只训练两个小因子。现在再问：既然基座不更新，能否用更紧凑的格式保存它？可以，但要区分**存储格式、算子计算 dtype、可训练参数/优化器状态 dtype**。这三者可以不同。

用符号写出一个量化适配层：

$$h=\operatorname{dequant}(q,s)x+\frac\alpha r BAx.$$

q 是离散码字，s 是量化尺度，二者在本项目中冻结。A、B 是可训练高精度参数。输入仍能通过反量化后的基座运算获得梯度；“冻结量化权重”不等于“整个前向不可微”。我们不对最近邻码字选择求导，也不需要为冻结基座构造 straight-through estimator。

## 02 · QLoRA：存储精度和计算精度分开看

QLoRA 的核心是冻结量化后的基座权重，同时训练较高精度的 LoRA 适配器。需要矩阵运算时按实现使用反量化后的值参与计算，梯度传到适配器；4bit 不是“整个训练都在4bit中进行”。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

论文中的关键组成包括 NF4、double quantization 和 paged optimizers。NF4 面向近似正态的权重分布构造非均匀量化表示；它不是普通均匀 INT4，也不是4位浮点算术计算格式。double quant 进一步压缩量化常数；paged optimizer 处理显存峰值，不等于模型权重可以无限放进 GPU。

本项目实现 **NF4 基座 + double quant + LoRA + 普通 AdamW**。没有自动启用 paged optimizer，也不宣称复现论文的全部优化。这样可以直接沿用上一节点的优化器与检查逻辑。

## 03 · 从均匀量化理解 NF4：码字不是浮点权重本身

b bit 存储最多有 $2^b$ 种状态。4bit有16个码字；它只决定“可以选16种表示”，并未规定这16种数值等间距。均匀量化把区间按固定间隔划分；非均匀码本把更多表示分配给更常出现的区域。NF4 的动机来自近似正态权重分布，在零附近安排较密的表示，并包含精确零。

对一个权重块 $w_1,\ldots,w_B$，先取 $s=\max_i|w_i|$，归一化 $u_i=w_i/s$。再从固定码本 c 中找最近值：

$$q_i=\arg\min_{k\in\{0,\ldots,15\}}|u_i-c_k|,\qquad \hat w_i=s\,c_{q_i}.$$

课堂显示的 NF4 码本以 bitsandbytes 的实现值为依据，四舍五入展示。零附近例如 −0.09105、0、0.07958、0.16093、0.24611；它不是简单地给所有区间相同宽度，也不应据此假设所有权重分布都适合 NF4。权重分布与分组策略会影响误差。[码本实现](https://github.com/bitsandbytes-foundation/bitsandbytes/blob/main/bitsandbytes/backends/utils.py)

手算例子：若s=1、w=0.2，最近码本值是0.16093，恢复值约0.16093，误差−0.03907。如果同块出现离群值6，则u=0.03333，最近值变成0，恢复权重也为0。这个例子说明 scale 是共享耦合点：改变一个大权重可能改变同块多个小权重的分辨率。更小块通常能减少这种耦合，但需要保存更多 scales。

[[LAB:nf4]]

```python
# 教学级参考：展示算法，不打包4bit，也不替代 bitsandbytes kernel
scale = weights.abs().max().clamp_min(1e-12)
normalized = weights / scale
codes = (normalized[:, None] - nf4_codebook[None, :]).abs().argmin(-1)
restored = nf4_codebook[codes] * scale
mse = (restored - weights).square().mean()
```

量化误差不是神秘噪声，它会在矩阵运算中形成 $Ex$，其中 $E=\hat W-W$。同一个 E 对不同输入 x 的影响不同，所以权重 MSE 小不保证下游分类误差小。LoRA 可以学习某些任务相关补偿，但其低秩容量与训练数据有限，不能保证恢复所有信息。必须保留 NF4 未适配基线才能分清量化本身的影响。

## 04 · Double quantization：为什么连尺度也值得压缩

按每64个权重共享一个 FP32 scale 计算，scale 成本为 $32/64=0.5$ bit/weight；因此“4bit权重”实际至少约4.5bit/weight，尚未计其它元数据。若把这些 scales 再做8bit块量化，每256个一级scale共享一个FP32二级scale，则近似成本变为：

$$4+\frac8{64}+\frac{32}{64\times256}\approx4.127\ \text{bit/weight}.$$

节省约0.373bit/weight，来源是量化常数压缩，并非把4bit权重又压成2bit。对7B参数，粗略节省 $7\times10^9\times0.373/8$ 字节，约0.304GiB；这只是理想分组载荷估算，实际内存受未量化层和元数据影响。[QLoRA 的 double quantization 设计](https://arxiv.org/abs/2305.14314)

算法上有两次恢复：先从二级码恢复一级scale，再用该scale恢复权重。若scale有误差δs，单个权重额外误差是 $\delta s\,c_q$。所以 double quant 也有精度代价，只是压缩对象换成了scales。下面用均匀8bit教学量化演示中心化、编码、恢复；它不逐位模拟 bitsandbytes 的完整嵌套格式。

## 05 · 按正确顺序准备模型

```python
compute_dtype = (torch.bfloat16 if torch.cuda.is_bf16_supported()
                 else torch.float16)
quant = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=compute_dtype)
base = AutoModelForCausalLM.from_pretrained(
    model_id, revision=model_sha, quantization_config=quant,
    torch_dtype=compute_dtype, device_map={"": 0})
base = prepare_model_for_kbit_training(base)
model = get_peft_model(base, lora_config)
model.config.use_cache = False
```

先准备量化基座，再注入 adapter，避免后续冻结操作把刚加入的可训练权重一起冻结。检查可训练参数和实际 dtype，不要根据变量名假定所有 adapter 都是 BF16：PEFT 可能为稳定性保留或提升适配器精度。[PEFT 量化训练指南](https://huggingface.co/docs/peft/v0.18.0/developer_guides/quantization)

本实现单 GPU 固定 `device_map={"": 0}`，不使用推理场景常见的自动跨设备分配作为训练方案。若改成多卡/FSDP，需要重新设计加载、分片与优化器路径，不能仅改一个 device_map。[Transformers bitsandbytes 文档](https://huggingface.co/docs/transformers/v4.57.3/en/quantization/bitsandbytes)

## 06 · 做显存账本，不做“4bit等于四分之一”的推断

近似分解训练峰值：

$$M\approx M_{base}+M_{adapter}+M_{grad}+M_{optimizer}+M_{activation}+M_{workspace}.$$

理想化的 P 个4bit权重占 $P/2$ 字节，但实际还有分组量化常数、未量化层、对齐和临时缓冲区。LoRA 只减少可训练参数对应的梯度/优化器状态；QLoRA 额外压缩基座存储。长序列或大 microbatch 下，激活仍可能主导峰值。

```python
torch.cuda.reset_peak_memory_stats()
# 至少经过一次完整 forward/backward/optimizer.step 后再读
allocated = torch.cuda.max_memory_allocated() / 2**30
reserved = torch.cuda.max_memory_reserved() / 2**30
print({"allocated_GiB": allocated, "reserved_GiB": reserved})
```

allocated 是张量分配峰值，reserved 是缓存分配器保留峰值；它们都不保证等于 nvidia-smi 看到的进程占用。首次优化器 step 才可能创建 Adam 状态，因此只测模型加载后的数字会漏算训练成本。

## 07 · 激活 checkpointing：反向所需的信息何时保存

参数冻结之后仍有激活开销。计算某层参数梯度时，需要该层的输入；计算输入梯度时，需要相应局部导数。普通 autograd 保存反向所需的张量，层数与序列长度增大后这部分开销显著。激活 checkpointing 只保存段边界，反向到达该段时重新执行部分前向，恢复内部张量再计算梯度。

考虑4个串行块 $h_i=f_i(h_{i-1})$。普通方案保留h0到h4；按每2块分段的方案保留h0、h2、h4，反向段2时重算h3，反向段1时重算h1。示意前向算子总调用从4次增为6次，但 optimizer.step 仍只有一次。真实实现可能重算更多或更少，且有临时缓冲，不能把“保存3个节点”直接换算为真实CUDA峰值。[重算换内存的算法背景](https://arxiv.org/abs/1604.06174)

[[LAB:checkpoint]]

使用 checkpointing 时，重算路径要与原始前向一致。Dropout 的随机状态、可变全局状态或条件分支都可能破坏等价性；应遵循 PyTorch 的 checkpoint 配置与 RNG 规则。本课程使用模型库支持的 gradient checkpointing 接口，关闭 `use_cache`，并记录开启/关闭的步耗时和峰值。

## 08 · OOM 的排查顺序

先记录失败发生在加载、前向、反向还是更新。加载时失败，检查模型大小、量化是否真正生效和设备放置；前向/反向失败，先降低 microbatch 与 max_length，开启 gradient checkpointing；更新时失败，检查 trainable 集合和 optimizer 状态。降低累积步数通常不会降低单个 microbatch 的激活峰值。

Gradient checkpointing 通过重算部分前向换显存，不能免费加速。把开启/关闭时的步耗时与峰值放在一起比较。对本项目的0.5B模型，QLoRA未必比普通 LoRA 更快；反量化开销、小矩阵效率和设备共同影响吞吐，应测量而非预设结论。

## 09 · 公平比较需要四组结果

运行未适配的高精度基线、未适配的 NF4 基线、LoRA、QLoRA。只比较 LoRA 与 QLoRA 会把量化对初始模型的影响和训练影响混在一起。四组使用同一模型 SHA、测试集 hash、prompt、输出上限和确定性解码。

**节点作业 D · 显存与效果实验。** 在同一张 GPU 上固定 r、alpha、数据与步数，运行两种训练配置；补充 NF4 基线。提交四组 schema valid / exact match / macro F1 与逐例结果，训练 allocated/reserved 峰值、耗时、GPU型号、软件版本。至少解释一个内存账本无法精确预测的实测差异。没有 GPU 时可先写实验协议并通过 CPU 测试，但该节点的训练验收保持未完成。


## 10 · 从配置到证据：如何判断 QLoRA 真的启用了

只看到 `load_in_4bit=True` 不够。需要同时检查量化模块类型、量化配置、实际设备、trainable 参数清单以及一次完整训练 step。以下三类结论必须分开写进报告：

| 结论 | 所需证据 | 不能用什么替代 |
|---|---|---|
| 基座采用4bit加载 | 模块类型与 quantization_config | 配置文件里写了NF4 |
| 只训练adapter | requires_grad清单、梯度与冻结检查 | optimizer初始化未报错 |
| 节约实际显存 | 同设备同任务的完整step峰值 | 理想4bit字节数 |

Paged optimizer 是借助统一内存管理优化器状态驻留的资源机制，处理峰值时可能引入主机/设备迁移；它不改变 AdamW 的损失或矩估计公式。本项目没有开启它，因此不把其潜在收益计入报告。若未来加入，应把它作为新的受控实验，而不是沿用当前结果宣称已验证。

**加深作业 D2 · 量化误差审计。** 用 `numerical_walkthrough.py` 的 NF4 参考函数，构造含/不含离群值的同一块，导出每个权重的原值、scale、code、恢复值、误差；比较块MSE与对两个不同输入x的输出误差。再解释为什么 double quant 误差和 LoRA 训练损失不是同一个量。正式GPU实验要提交真实输出，课堂动画的数字不能充当显存或效果测量。

**理解检查。** q 是码字索引，不能直接与浮点 BA 相加；反量化只解码，不会恢复舍入丢失的信息；gradient checkpointing 与保存训练 checkpoint 是两种不同机制，前者重算激活，后者服务于故障恢复。
