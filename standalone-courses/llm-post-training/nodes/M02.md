## 01 · 学习目标与张量地图

本节点完成后，你应能从一条工单逐步追踪到一次参数更新，而不是只会调用 Trainer。需要掌握的背景是：条件概率、矩阵乘法与导数。我们先解释输入形状和计算图，再推导 token loss，最后把它们接到可运行的 PyTorch 循环。

| 张量 | 形状示例 | 含义 |
|---|---|---|
| input_ids | [B,T] | 词表 id，不是连续特征 |
| attention_mask | [B,T] | 真实位置1、padding位置0；模型再结合因果规则 |
| hidden states | [B,T,d] | 每个位置的上下文表示 |
| logits | [B,T,V] | 每个位置预测下一 token 的词表分数 |
| labels | [B,T] | 目标 token id 或 ignore_index=−100 |

B 是 microbatch 样例数，T 是批内补齐后的长度，V 是词表大小，d 是隐藏维度。例如 logits[:,7,:] 是所有样例在第7个输入位置的分数，它对应的 next-token 标签位于第8个位置。先在纸上画这个关系，可以避免最常见的双 shift 错误。

## 02 · 背景：注意力掩码与监督掩码控制两件不同的事

单头注意力计算 $Q=XW_Q,K=XW_K,V=XW_V$，然后 $H=\operatorname{softmax}(QK^\top/\sqrt{d_k}+M)V$。Q/K 决定读取权重，V 提供被读取的信息。$M$ 对未来位置或不可读位置加 $-\infty$，softmax 后这些位置权重为0。缩放 $\sqrt{d_k}$ 是为了控制点积随维度增大时的量级，不是 loss 的归一化分母。[原始注意力定义](https://arxiv.org/abs/1706.03762)

训练一次处理整段真实序列，但通过因果 mask 让位置 t 只能读取前缀，因此不同位置的 next-token 任务可以并行计算。推理却必须等生成新 token 后才能形成下一个条件，这解释了训练与生成在执行方式上的差异。

`labels=-100` 在交叉熵阶段忽略某个目标，不改变注意力。误把 prompt 的 attention_mask 设为0，会把任务描述和用户输入从条件中排除。反过来，只屏蔽 padding 的 labels 而不屏蔽注意力，真实 token 可能读取不该读取的 padding 表示。两种掩码都应按各自契约构造。

## 03 · SFT 是有条件的下一个 token 预测

假设一条序列由 system、user、assistant 组成。模型对所有位置执行前向传播；我们只对目标回答和结束标记计算损失。`attention_mask` 控制 padding 是否参与注意力，`labels=-100` 控制该位置是否参与交叉熵。两者不能互换。

本课程在 `core.py` 使用**单轮、completion-only** 方案。若扩展多轮对话，要明确监督所有 assistant turn 还是只监督最后一轮，并使用真正的 assistant span mask；不要搜索字符串 `assistant` 来猜边界。[Transformers chat template 说明](https://huggingface.co/docs/transformers/v4.57.3/en/chat_templating)

```python
prompt = tokenizer.apply_chat_template(
    messages, tokenize=True, add_generation_prompt=True)
full = tokenizer.apply_chat_template(
    messages + [answer], tokenize=True, add_generation_prompt=False)
assert full[:len(prompt)] == prompt
labels = [-100] * len(prompt) + full[len(prompt):]
```

这段断言很重要：并不是所有模板的前缀都稳定。断言失败时应实现该模板的 assistant mask，不能静默继续。直接使用模板的 token 输出，也避免“先渲染特殊 token，再编码时重复加 BOS/EOS”。超长样例在项目中直接报错，先清洗或重新划分上下文，不把目标回答截断成残缺 JSON。

## 04 · 因果位移：第 t 位预测第 t+1 位

输入 `[prompt, A, B, EOS]` 时，prompt 最后一个位置的 logit 预测 A；A 所在位置预测 B。我们显式位移一次：

```python
# project/core.py::causal_loss_sum
shift_logits = logits[:, :-1, :].contiguous().float()
shift_labels = labels[:, 1:].contiguous()
loss_sum = F.cross_entropy(
    shift_logits.reshape(-1, logits.size(-1)),
    shift_labels.reshape(-1), ignore_index=-100, reduction="sum")
num_targets = (shift_labels != -100).sum()
loss = loss_sum / num_targets
```

如果改为 `model(..., labels=labels).loss`，多数 Transformers causal LM 已在内部完成 shift；不要再位移一次。项目选择显式 loss，所以调用模型时不传 labels。零个有效目标应直接报错，防止产生 NaN 或“没有学到任何东西”的训练。

## 05 · 手推 softmax 交叉熵：从 logit 到 p−y

给定词表 logits $z\in\mathbb R^V$，$p_i=e^{z_i}/\sum_j e^{z_j}$。目标类别为 k 时，交叉熵 $L=-\log p_k=-z_k+\log\sum_j e^{z_j}$。对任意 logit $z_i$ 求导：第一项贡献 $-1[i=k]$，第二项贡献 $e^{z_i}/\sum_j e^{z_j}$，因此

$$\frac{\partial L}{\partial z_i}=p_i-1[i=k].$$

这不是要背的技巧，而是训练方向的解释：目标类别的梯度为负，梯度下降会提高它的 logit；其它类别梯度为正，其 logit 被压低。所有梯度之和为0，与“给所有 logits 同时加一个常数不改变 softmax”一致。

数值例子：z=[2,1,0]、目标 k=1（从0开始计数）。softmax约为[0.6652,0.2447,0.0900]，loss约1.4076，梯度约[0.6652,−0.7553,0.0900]。使用η=0.5的局部 SGD 后，logits变为[1.6674,1.3776,−0.0450]，目标概率提高。真实模型不是直接存三个可训练 logits，而是用这个梯度继续传到输出投影与各层参数。

为避免 exp(1000) 溢出，取 $m=\max z$，计算 $\log\sum e^{z_i}=m+\log\sum e^{z_i-m}$。不要先显式 softmax 再取 log，优先使用 `F.cross_entropy` 或 `F.log_softmax`。

[[LAB:softmax]]

```python
z = torch.tensor([2., 1., 0.], requires_grad=True)
loss = torch.nn.functional.cross_entropy(z[None], torch.tensor([1]))
loss.backward()
expected = z.detach().softmax(-1) - torch.tensor([0., 1., 0.])
torch.testing.assert_close(z.grad, expected)
# 没有量化/离散步骤时，可用中心差分核对解析梯度
# dL/dz_i ≈ (L(z+eps*e_i)-L(z-eps*e_i)) / (2*eps)
```

## 06 · 链式法则与 autograd：冻结不等于切断

损失通常通过许多中间变量依赖参数。若 $h=ax,\hat y=bh,L=\frac12(\hat y-t)^2$，则 $\partial L/\partial a=(\hat y-t)\,b\,x$。取 x=2、a=0.5、b=3、t=4，输出3、误差−1，得到 dL/da=−6。即使 b 冻结不更新，它仍是导数链中的乘数。

PyTorch 在 forward 时建立计算图，backward 由输出向输入应用局部导数并累加到叶子参数的 `.grad`。`requires_grad_(False)` 表示不为该参数累计梯度；`detach()` 或把整段 forward 包进 `no_grad()` 则可能切断上游学习路径。LoRA 尤其需要这个区别：冻结的基座层之间插有可训练 adapter，不能把整个基座计算粗暴关闭 autograd。

[[LAB:backprop]]

```python
a = torch.tensor(.5, requires_grad=True)
b = torch.tensor(3.)  # 冻结参数
h = a * 2
loss = .5 * (b * h - 4).square()
loss.backward()
assert a.grad.item() == -6
# 若改成 b * h.detach()，此例已无可训练路径，backward 会报错。
```

反向传播会把同一参数在所有位置、所有路径收到的贡献相加。梯度爆炸可以来自长链条和多个分支，不是某个 token 的概率简单“太小”就能完整解释。遇到 NaN，应定位首次出现非有限值的位置，检查输入、loss、梯度和 dtype；不能只用更强裁剪掩盖错误。


## 07 · Padding 的陷阱：pad id 可能等于 eos id

```python
# 对短序列补齐到批内最大长度，按位置补 -100
input_ids = sequence + [pad_id] * pad_length
attention_mask = [1] * len(sequence) + [0] * pad_length
labels = target_labels + [-100] * pad_length
```

不要用 `labels[input_ids == pad_id] = -100`：当 pad 与 EOS 共享 id，会连真实结束标记也消掉。模型因此可能学不好何时结束。项目测试特意使用 `pad_id == eos_id`，验证真正的 EOS 仍然受监督。

## 08 · 从 forward 到 optimizer.step

单步训练由取 batch、前向、计算损失、反向、梯度裁剪、更新和清梯度组成。梯度累积允许在显存不变的情况下增加一次更新看到的样例数，但并不会缩小每个 microbatch 的激活开销。

```python
# window 是最多 accumulation 个 microbatch；最后一个窗口可能不足
N = sum((b["labels"][:, 1:] != -100).sum().item() for b in window)
optimizer.zero_grad(set_to_none=True)
for batch in window:
    with torch.autocast("cuda", dtype=compute_dtype):
        logits = model(input_ids=batch["input_ids"],
                       attention_mask=batch["attention_mask"]).logits
        loss_sum, _ = causal_loss_sum(logits, batch["labels"])
    scaler.scale(loss_sum / N).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(trainable_parameters, 1.0)
scaler.step(optimizer)
scaler.update()
```

重点是分母 $N$。若每个 microbatch 回答长度不同，简单平均各 batch 的平均 loss 会赋予短回答不同权重。显式累加 token loss、除以窗口内有效目标总数，实现 token 加权目标；末尾不足的窗口也自然正确。BF16 通常不需要 loss scaling；项目只在 FP16 路径启用 GradScaler。[PyTorch AMP 示例](https://docs.pytorch.org/docs/stable/notes/amp_examples.html)

本实现单卡、无 packing。有效样例 batch 约为 microbatch × accumulation；有效目标 token 数仍随文本变化。多卡时还必须处理跨 rank token 归一化及 DDP 梯度平均，不应直接把本循环复制后声称等价。

## 09 · 梯度累积的等价条件：分母属于整个窗口

假设第一个 microbatch 有2个有效 token，每个 token 梯度为1；第二个有10个，每个梯度为3。正确 token 均值梯度是 $(2\times1+10\times3)/12=2.6667$。分别算均值再取平均得到 $(1+3)/2=2$，相当于让短回答每个 token 获得更大权重。

因此整个窗口有 N 个有效目标时，每个 microbatch 反传 `loss_sum / N`。每次 backward 都追加梯度，所有 microbatch 完成后仅调用一次 optimizer.step。若每个 microbatch 后清梯度或更新参数，就不再等价于同一个参数点上计算大 batch 梯度。Dropout 的随机路径及浮点求和次序可能造成数值差异，因此等价性测试应关闭随机 dropout 并设置容差。

[[LAB:accumulation]]

本项目把窗口中每个 batch 的标签数预先统计出来。这个方案适合单卡且长度已知的小窗口；更大规模的数据流可能需要不同的分布式归一化方案。若自己扩展 DDP，要推导 all-reduce 是求和还是平均、不同 rank 的目标 token 数是否相同，不能机械乘 world_size。

## 10 · AdamW 的每一步：裁剪、一阶矩、二阶矩和衰减

SGD 用 $\theta\leftarrow\theta-\eta g$。Adam 在此基础上维护一阶矩 m 和平方梯度的二阶矩 v，分别用于方向平滑和按坐标缩放。默认常见参数是β₁=0.9、β₂=0.999，但它们仍属于实验配置：

$$m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\quad v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2.$$

初始 m、v 为0，早期估计偏向0，故用 $\hat m_t=m_t/(1-\beta_1^t)$、$\hat v_t=v_t/(1-\beta_2^t)$ 校正。AdamW 把权重衰减从梯度自适应缩放中分离：

$$\theta_t=(1-\eta\lambda)\theta_{t-1}-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}.$$

例如首个梯度为2，m₁=0.2、v₁=0.004，但校正后 $\hat m_1=2,\hat v_1=4$，归一化更新量接近η，而不是0.2η。weight decay 并非总与“在 loss 中加 L2 正则”效果相同，因为后者也会进入自适应矩估计。[PyTorch AdamW 定义](https://docs.pytorch.org/docs/2.8/generated/torch.optim.AdamW.html)

全局范数裁剪使用 $g\leftarrow g\min(1,c/(\|g\|_2+\varepsilon))$。它保持整个拼接梯度方向，仅缩短过大的长度；与逐元素 clamp 不同。AMP 的 FP16 loss scaling 会先放大梯度，所以必须在裁剪前 `unscale_`。如果仍有非有限梯度，GradScaler 可能跳过参数更新；日志应区分“完成一个 batch”和“确实更新一次参数”。

[[LAB:optimizer]]

```python
params = [p for p in model.parameters() if p.requires_grad]
optimizer = torch.optim.AdamW(params, lr=2e-4, weight_decay=0.01)
# 当使用 FP16 GradScaler 时，先 unscale，再裁剪；BF16路径通常关闭 scaling
scaler.unscale_(optimizer)
grad_norm_before_clip = torch.nn.utils.clip_grad_norm_(params, 1.0)
scaler.step(optimizer)
scaler.update()
```

AdamW 为可训练参数维护状态；LoRA 减少这部分参数，QLoRA 又压缩冻结权重。两种收益来源由此相互独立。学习率过大可能跳过局部低损失区域，过小则在预算内学不到足够变化；先确认梯度路径和数据正确，再在 dev 上调学习率。

## 11 · 训练是否真的发生：看证据链

先用 8–16 条样例尝试过拟合，检查 loss 是否明显下降；这只能验证管线。再切回正式 split，比较 train/dev token NLL 和真实生成指标。如果 train 降而 dev 升，排查过拟合、学习率与数据分布；如果 NLL 降而 JSON 失败率升，检查停止 token、模板和解码。

保存 adapter 不是保存完整训练状态。项目在 epoch 边界保存 optimizer、scaler、RNG、步数和 epoch；中途故障重跑当前 epoch。最终验收还要在新进程重载 adapter，确认同一输入产生一致的 logits（规定浮点容差）。
