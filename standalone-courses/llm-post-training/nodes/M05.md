## 01 · 结课项目：交付一个可复现的任务适配实验

你要交付一个工单结构化模型，以及让另一位工程师复核结果的完整证据。任务沿用 M01 的 category / priority 契约。本项目借鉴大学实验课“基线 → 控制变量 → 实现 → 评估”的组织方式，代码与任务独立设计；Stanford 原作业涉及更广泛的对齐与 RL 内容，可以作为扩展。[CS336 Assignment 5](https://github.com/stanford-cs336/assignment5-alignment)

建议投入：正文与视频约5–7小时，项目实现、GPU实验与报告约6–10小时；运行时间取决于数据和硬件。已有 Python、线性代数与 autograd 基础是前提。

## 02 · 环境：先检查，再启动训练

| 项目 | 参考配置 | 为什么需要记录 |
|---|---|---|
| 操作系统 | Linux x86_64；CPU测试支持 macOS | bitsandbytes 的设备后端不能混为一谈 |
| Python / PyTorch | 3.12 / 2.8.0 | 可重建依赖与算子行为 |
| GPU | 单张 NVIDIA，建议16GB起步 | 只针对0.5B、512 token、microbatch1的起始预算，须实测 |

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126

```

CPU/macOS 冒烟测试用 `pip install torch==2.8.0 -r requirements.txt` 替代 GPU 安装命令。测试不下载模型；正式 train/evaluate 首次需要下载基座。CUDA wheel 不是驱动，先用 nvidia-smi 检查硬件与驱动，再参考 [PyTorch 安装版本表](https://pytorch.org/get-started/previous-versions/)。环境不足时降低规模或使用已有远程 GPU，不需要为了浏览课程购买资源。

## 03 · 数据验收：样例数据不是正式数据集

下载包的合成样例用于检查管线。模板在 split 间重复，分数不能说明泛化。正式提交要求 train≥300、dev≥60、test≥60 条人工审核样例，覆盖三类类别与两种优先级；报告不平衡情况。按真实事件、客户或模板族隔离，测试集在调参前冻结。

去重检查是底线。两句话措辞不同，也可能表达同一个事件；只检查 id 或字符串 hash 不足以防止泄漏。报告至少抽查20对最相似跨 split 样例，说明如何判定。真实客户数据需脱敏并确认使用权限；也可人工编写独立事件集。

## 04 · 实验矩阵与复现命令

```bash
python train.py --config configs/lora.json
python train.py --config configs/qlora.json
python evaluate.py --config configs/lora.json --output runs/baseline-float.json
python evaluate.py --config configs/qlora.json --output runs/baseline-nf4.json
python evaluate.py --config configs/lora.json --adapter runs/lora --output runs/lora-test.json
python evaluate.py --config configs/qlora.json --adapter runs/qlora --output runs/qlora-test.json
```

先在 dev 上选择配置，再对冻结 test 进行最终比较；不要每次看 test 后调学习率。r=16 消融复制配置到新文件，设置 alpha=32 和新的 output 目录。模型版本必须是明确 commit SHA；prepare --pin 会把两份配置固定到同一个版本，报告还要保留 tokenizer/chat template 与数据指纹。

## 05 · 管理代码，也管理实验产物

```text
ticketlab/
  core.py, train.py, evaluate.py, prepare.py
  configs/             # 每次实验的声明配置，进入 Git
  tests/               # 掩码、梯度和重载测试，进入 Git
  data/                # 数据卡 + 合法公开数据/获取脚本
  reports/             # 协议、对比表、错误分析、产物索引
  runs/                # 日志、adapter、checkpoint，不进入普通 Git
```

Git 应能回答三个问题：这次运行用哪版代码、哪版数据和哪份配置。用 `experiment/lora-r8` 等分支保存变化；每个可复现实验保留 commit，交付打 `submission-v1` tag。秘密、私有原始数据、大型权重和虚拟环境不提交。需共享的大产物放对象存储或 Git LFS/DVC，索引记录 SHA256、URI 和权限。README 必须给出从空环境到复现指标的命令。

`adapter/` 是推理/继续适配产物，`training.pt` 才包含继续训练的 optimizer/scaler/RNG。当前代码只支持 epoch 边界恢复。把两者区别写入交付文档，避免“可以重载权重”被误认为“可以精确续跑”。

## 06 · 最终验收：80分且四条硬门槛通过

| 维度 | 分值 | 必须提供的证据 |
|---|---:|---|
| 数据与任务 | 20 | 标签政策、许可/来源、300/60/60+、分组隔离和近重复审计 |
| SFT正确性 | 25 | 测试、token/label对齐、EOS、shift、累积末窗解释 |
| LoRA/QLoRA | 20 | 可训练清单、两种配置、rank消融、真实显存与耗时 |
| 评估 | 20 | 四组逐例结果、三项指标、至少10个错误案例 |
| 复现与管理 | 15 | 固定版本与指纹、环境快照、重载验证、Git tag |

**硬门槛：无已知数据泄漏；无全mask/双shift；基座未被意外更新；adapter能重新加载。** 效果未提升并不自动不及格，缺少证据或隐藏失败才会使结论失效。报告要解释哪个假设被支持，哪个被否定，下一步实验如何区分原因。

最终提交 `reports/report.md`（2–4页）、实验结果与可访问的仓库 tag。完成下方检查清单只记录你的自查，不代表系统已经运行 GPU 或自动评分。
