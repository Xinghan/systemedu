## 01 · 先补线性代数：矩阵、秩和更新方向

LoRA 的重点不是“把一个大模型变小”，而是限制一次任务适配能怎样改变权重。需要先区分模型原本的表示能力与本次训练新增的自由度。预训练权重仍参与前向；小规模 adapter 只描述从这个起点出发的增量。

矩阵 $W\in\mathbb R^{d_{out}\times d_{in}}$ 表示从输入向量到输出向量的线性映射。矩阵的列空间是它能输出的向量所张成的空间；秩是这个空间的维数。rank1 矩阵可以写成列向量与行向量的外积 $ba^\top$，作用在 x 上时，先算标量 $a^\top x$，再沿固定方向 b 放大或缩小。

例如 $a=[1,0,1]^\top,b=[1,2,0]^\top$，则 $ba^\top$ 的三行分别为[1,0,1]、[2,0,2]、[0,0,0]。所有输出都落在 b 的一维直线上。若输入 x=[1,2,−1]，$a^\top x=0$，输出就是零；这不是实现故障，而是该输入恰好落在 a 的零空间。

多个外积相加得到 $BA=\sum_{k=1}^{r}b_ka_k^\top$，所以输出落在 B 的至多 r 维列空间中。这里的“至多”很重要：若不同列线性相关，实际秩会更低。LoRA 在训练中学习 A、B 的方向与幅度，并不事先固定一组语义概念轴。

## 02 · 冻结 W，学习一个低秩增量

对线性层 $W_0\in\mathbb R^{d_{out}\times d_{in}}$，LoRA 将更新参数化为：

$$h=W_0x+\frac{\alpha}{r}BAx,\quad A\in\mathbb R^{r\times d_{in}},\quad B\in\mathbb R^{d_{out}\times r}.$$

$W_0$ 冻结，只训练 $A,B$。这里约束的是 **更新矩阵** 的秩至多为 $r$，不是把整个预训练权重矩阵宣称为低秩。参数数量从 $d_{in}d_{out}$ 变成 $r(d_{in}+d_{out})$。这是参数化的节省，不是总显存按同样比例下降。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

以一个 4096×4096 层为例，r=8 时新增 65,536 个参数，约为原层的 0.39%。但 Transformer 有许多层和投影；模型总体 trainable ratio 必须从实际注入后的模型统计。

[[LAB:lora]]

**矩阵维度检查。** 本文用列向量记号 $BAx$；PyTorch 的 batch 输入通常把样例放在行上，形状为[B,d_in]，等价实现是 `(x @ A.T) @ B.T`。别把论文中的乘法顺序直接抄到行向量代码里。维度能相乘仍不保证语义正确，应同时核对输出 shape 和数值。

## 03 · 容量、缩放与成本必须分开估算

对一个4096×4096线性层，全参数有16,777,216个权重；r=8的 adapter 只有 $8(4096+4096)=65,536$ 个。前向新增两次小矩阵乘法，单输入向量的乘加量级约 $r(d_{in}+d_{out})$；但基座乘法仍然执行。因此训练参数比例0.39%不意味着总计算量或总峰值显存只剩0.39%。教学动画的3×3矩阵在r=2时反而有12个adapter参数，多于原来的9个；一般只有 r < d_in·d_out/(d_in+d_out) 才减少这一层参数。小矩阵用于看清乘法，不用于证明节省比例。

若 adapter 权重、梯度、一阶矩、二阶矩都以 FP32 保存，仅这四项约16字节/可训练参数，65,536个参数约1 MiB。真实混合精度配置可能有不同 dtype 或额外 master copy，应从运行时统计；这个算例只是把“参数数目”转成资源账本的方法。

缩放 $s=\alpha/r$ 用来控制分支量级。固定α时，提高r同时降低单因子乘积前的系数；保持s不变则需要同步增加α。即使s相同，不同初始化维度和训练动力学仍可能不同。因此 rank 消融的目标是尽可能控制变量，不是声称两个实验除了表达能力绝对等价。

LoRA 的低秩假设是“任务所需更新可以在较低维空间中有效表示”的经验动机，不能推断任何任务都能被任意小的r解决。若学习受限，可能是容量不足，也可能是目标模块错误、数据缺失或优化失败。要用 train/dev、模块消融和冻结检查逐步区分。[LoRA 的方法与实证分析](https://arxiv.org/abs/2106.09685)


## 04 · 用 12 行代码理解梯度路径

```python
class LoRALinear(torch.nn.Module):
    def __init__(self, frozen_linear, r=8, alpha=16):
        super().__init__()
        self.base = frozen_linear.requires_grad_(False)
        self.A = torch.nn.Parameter(torch.empty(r, self.base.in_features))
        self.B = torch.nn.Parameter(torch.zeros(self.base.out_features, r))
        torch.nn.init.kaiming_uniform_(self.A, a=5 ** 0.5)
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * ((x @ self.A.T) @ self.B.T)
```

这是解释用单层代码；训练项目使用 PEFT 完成多层注入。初始 B=0，因此增量为 0，模型开始时保持原有输出。第一步通常 B 得到非零梯度，A 的梯度可能为 0；B 更新后 A 才得到信号。因此“第一步 A 没变化”不直接证明实现坏了；若 A、B 都初始化为 0，则两者梯度可能一直为 0。

冻结基座参数只是不为它们存梯度/优化器状态。为了训练较早层的 adapter，梯度仍要经过基座运算向前传播链的上游回传，激活与计算成本仍然存在。

## 05 · 推导 A 与 B 的梯度：不对称初始化的原因

把一个线性层写成 $h=W_0x+sBAx$。设上游梯度 $g=\partial L/\partial h$（d_out维列向量），中间激活 $u=Ax$（r维）。通过向量外积形式可得到：

$$\frac{\partial L}{\partial B}=s\,g\,u^\top=s\,g\,(Ax)^\top,\qquad\frac{\partial L}{\partial A}=s\,(B^\top g)\,x^\top.$$

第一条的形状为[d_out,r]，第二条为[r,d_in]，与参数一一对应。对一个 batch，应累加每个样例的外积贡献；如果 loss 用均值，梯度也按同一分母归一化。自动求导负责计算，但你仍应能解释 shape、符号和何时为零。

当 B=0、A随机时，初始增量为0，前向输出保持基座起点；dL/dA=0，而 dL/dB 可能非零。第一次 optimizer.step 更新B，第二次 backward 的 $B^\top g$ 就可能非零，A开始学习。若两者都为零，在这个双线性分支里两个梯度都为零，系统无法凭空离开这个点。这里假设没有其它改变零点的机制；不能把“权重衰减”当成让全零因子长出来的方法。

具体标量例子：x=2、A=0.5、B=0、冻结输出0、目标1，使用 $L=\frac12(y-1)^2$。第一次 dL/dB=−1、dL/dA=0，η=0.1更新后 B=0.1、A=0.5。第二次输出0.1，dL/dB=−0.9、dL/dA=−0.18，A终于开始变化。

[[LAB:loragrad]]

```python
# 与上面的手算采用相同数据；实际模型使用 CE，链式法则仍相同
A = torch.tensor(.5, requires_grad=True)
B = torch.tensor(0., requires_grad=True)
opt = torch.optim.SGD([A, B], lr=.1)
for step in range(2):
    opt.zero_grad(set_to_none=True)
    y = B * A * 2
    loss = .5 * (y - 1).square()
    loss.backward()
    print(step, A.grad.item(), B.grad.item())
    opt.step()
# 第0步: 0, -1；第1步: 约 -0.18, -0.9
```

对输入的梯度还包含 $W_0^\top g+sA^\top B^\top g$。这解释了冻结 W₀ 后为什么依然要执行它的反向路径：上一层可能有可训练参数，需要接收输入梯度。M02 的“冻结层标量网络”动画正是在演示这条路径。

## 06 · 用 PEFT 配置真实模型

```python
from peft import LoraConfig, get_peft_model
config = LoraConfig(
    task_type="CAUSAL_LM", r=8, lora_alpha=16,
    lora_dropout=0.05, target_modules="all-linear", bias="none")
model = get_peft_model(base_model, config)
model.print_trainable_parameters()
trainable = [(n, p) for n, p in model.named_parameters() if p.requires_grad]
assert trainable and all("lora_" in n for n, _ in trainable)
```

`target_modules="all-linear"` 是本项目的起点。PEFT 对预训练模型通常会排除输出层；要以实际匹配模块为准。若选 `q_proj, v_proj`，先用 `named_modules()` 确认架构的名字，不同模型可能把 QKV 合并在同一投影。不能只从教程复制层名。[PEFT LoRA 配置说明](https://huggingface.co/docs/peft/v0.18.0/developer_guides/lora)

三个超参应分开理解：r 决定增量子空间的容量；alpha/r 缩放增量；dropout 是训练正则。提高 r 不保证效果单调提高。对 r=8 与 r=16 做比较时，若要保持缩放系数相同，应同步将 alpha 从16改为32，并明确这项控制；固定 alpha 则同时改变容量与缩放。

## 07 · 验证更新、保存和复用

```python
frozen_before = {n: p.detach().clone() for n, p in model.named_parameters()
                 if not p.requires_grad}  # 仅用于小模型测试
# ... forward/backward/optimizer.step ...
for name, param in model.named_parameters():
    if name in frozen_before:
        assert param.grad is None
        assert torch.equal(frozen_before[name], param)
model.save_pretrained("runs/lora/adapter")
```

大模型上逐份复制权重会浪费显存；本测试在随机初始化的小模型上运行。训练现场检查 requires_grad、梯度和可训练参数清单，配合抽样或 CPU hash 验证。保存的 adapter 要绑定基座版本和 tokenizer；相同模型名不等于相同权重版本。

LoRA 也可以合并回普通线性权重以简化某些部署流程，但这不是所有量化格式的无损操作。尤其 QLoRA 不应直接把“加到4bit码字”当成合并；需要选定反量化/合并/重新量化路径并重新评估。本课程交付 adapter 加载路径，不进行量化权重合并。

## 08 · 把失败证据映射到可检验的假设

| 观察 | 可能原因 | 下一步检查 |
|---|---|---|
| trainable count 为0 | 注入失败或注入后又冻结 | 打印匹配模块和 requires_grad |
| 第一次 A 梯度为0、B非零 | 符合常见初始化 | 检查第二次 backward |
| 所有 adapter 梯度都为0 | 全mask、detach、两因子全零等 | 用 M02 的最小梯度算例定位 |
| train变好、dev恶化 | 数据量、过拟合、分布或训练预算 | 固定rank先检查早停与数据 |
| adapter保存后表现变了 | 基座SHA/模板/dtype/加载模式不一致 | 新进程核对logits与配置 |

**加深作业 C2。** 不调用 PEFT，实现上面的单层 LoRA，在小随机矩阵上验证两件事：① `s*((x@A.T)@B.T)` 与 `x@(s*B@A).T` 输出一致；② 手写 dA/dB 与 autograd 一致。报告初始与第二次 backward 的梯度范数，并解释为何“每个参数第一步必须非零梯度”是错误验收标准。大模型实验仍使用官方 PEFT，避免把教学层误当成完整适配器库。

**理解检查。** rank1 的更新加到满秩 W₀ 上，结果是否必为rank1？不是。若 A/B 的参数量很少，是否可以删除所有中间激活？不可以。为什么必须保存基座 SHA？adapter 只定义相对于特定基座的变化，换起点等于换模型。
