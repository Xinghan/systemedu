## 01 · 冻结 W，学习一个低秩增量

对线性层 $W_0\in\mathbb R^{d_{out}\times d_{in}}$，LoRA 将更新参数化为：

$$h=W_0x+\frac{\alpha}{r}BAx,\quad A\in\mathbb R^{r\times d_{in}},\quad B\in\mathbb R^{d_{out}\times r}.$$

$W_0$ 冻结，只训练 $A,B$。这里约束的是 **更新矩阵** 的秩至多为 $r$，不是把整个预训练权重矩阵宣称为低秩。参数数量从 $d_{in}d_{out}$ 变成 $r(d_{in}+d_{out})$。这是参数化的节省，不是总显存按同样比例下降。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

以一个 4096×4096 层为例，r=8 时新增 65,536 个参数，约为原层的 0.39%。但 Transformer 有许多层和投影；模型总体 trainable ratio 必须从实际注入后的模型统计。

## 02 · 用 12 行代码理解梯度路径

```python
class LoRALinear(torch.nn.Module):
    def __init__(self, frozen_linear, r=8, alpha=16):
        super().__init__()
        self.base = frozen_linear.requires_grad_(False)
        self.A = torch.nn.Parameter(torch.empty(r, self.base.in_features))
        self.B = torch.nn.Parameter(torch.zeros(self.base.out_features, r))
        torch.nn.init.kaiming_uniform_(self.A, a=5 ** 0.5)
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * ((x @ self.A.T) @ self.B.T)
```

这是解释用单层代码；训练项目使用 PEFT 完成多层注入。初始 B=0，因此增量为 0，模型开始时保持原有输出。第一步通常 B 得到非零梯度，A 的梯度可能为 0；B 更新后 A 才得到信号。因此“第一步 A 没变化”不直接证明实现坏了；若 A、B 都初始化为 0，则两者梯度可能一直为 0。

冻结基座参数只是不为它们存梯度/优化器状态。为了训练较早层的 adapter，梯度仍要经过基座运算向前传播链的上游回传，激活与计算成本仍然存在。

## 03 · 用 PEFT 配置真实模型

```python
from peft import LoraConfig, get_peft_model
config = LoraConfig(
    task_type="CAUSAL_LM", r=8, lora_alpha=16,
    lora_dropout=0.05, target_modules="all-linear", bias="none")
model = get_peft_model(base_model, config)
model.print_trainable_parameters()
trainable = [(n, p) for n, p in model.named_parameters() if p.requires_grad]
assert trainable and all("lora_" in n for n, _ in trainable)
```

`target_modules="all-linear"` 是本项目的起点。PEFT 对预训练模型通常会排除输出层；要以实际匹配模块为准。若选 `q_proj, v_proj`，先用 `named_modules()` 确认架构的名字，不同模型可能把 QKV 合并在同一投影。不能只从教程复制层名。[PEFT LoRA 配置说明](https://huggingface.co/docs/peft/v0.18.0/developer_guides/lora)

三个超参应分开理解：r 决定增量子空间的容量；alpha/r 缩放增量；dropout 是训练正则。提高 r 不保证效果单调提高。对 r=8 与 r=16 做比较时，若要保持缩放系数相同，应同步将 alpha 从16改为32，并明确这项控制；固定 alpha 则同时改变容量与缩放。

## 04 · 验证更新、保存和复用

```python
frozen_before = {n: p.detach().clone() for n, p in model.named_parameters()
                 if not p.requires_grad}  # 仅用于小模型测试
# ... forward/backward/optimizer.step ...
for name, param in model.named_parameters():
    if name in frozen_before:
        assert param.grad is None
        assert torch.equal(frozen_before[name], param)
model.save_pretrained("runs/lora/adapter")
```

大模型上逐份复制权重会浪费显存；本测试在随机初始化的小模型上运行。训练现场检查 requires_grad、梯度和可训练参数清单，配合抽样或 CPU hash 验证。保存的 adapter 要绑定基座版本和 tokenizer；相同模型名不等于相同权重版本。

LoRA 也可以合并回普通线性权重以简化某些部署流程，但这不是所有量化格式的无损操作。尤其 QLoRA 不应直接把“加到4bit码字”当成合并；需要选定反量化/合并/重新量化路径并重新评估。本课程交付 adapter 加载路径，不进行量化权重合并。
