## 01 · 学习路线：先建立概率模型，再选择训练方法

本节点要解决的不是记住一组缩写，而是读到一个训练方案时，能够回答四个问题：**模型的随机变量是什么？数据提供什么信号？损失如何产生梯度？哪些参数被更新？** 后续 SFT、LoRA 和 QLoRA 都沿着这四个问题展开。

建议先读本节背景，再观看上方 CS336 视频；观看时记录每一种方法的输入数据和目标函数。第一次遇到期望、log 概率或梯度，不必跳过：下面用一个只有三个目标 token 的例子建立直觉。全课会用同一个 TicketLab 项目连接数学、代码和工程验证。

| 符号 | 本课程中的含义 | 容易混淆的地方 |
|---|---|---|
| $x$ | 已知 prompt，包含任务描述和工单 | 它是条件，不是必须计入 loss 的目标 |
| $y=(y_1,\ldots,y_T)$ | 回答 token 序列，含结束标记 | 一个中文词可能对应多个 token |
| $\pi_\theta$ | 参数为 θ 的自回归语言模型 | 是条件概率分布，不是某个确定回答 |
| $\log\pi_\theta(y\mid x)$ | 完整回答的 log 概率 | 通常是目标 token 的 log 概率之和 |
| $\nabla_\theta L$ | loss 对参数的导数 | 小 loss 与好业务效果不是同一判断 |

## 02 · 背景：自回归语言模型到底学什么

分词器把文本映射为离散 token id。Embedding 将 id 映射为向量，Transformer 根据上下文形成隐藏表示，输出投影给词表中的每个候选 token 一个实数分数，叫作 **logit**。softmax 把这些分数变成和为1的概率。M02 会逐步推导这一步的损失和梯度；此处先把条件概率当作模型可计算的量。

概率链式法则把一个难以直接建模的整段回答概率分解为逐 token 条件概率：

$$\pi_\theta(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}),\qquad \log\pi_\theta(y\mid x)=\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t}).$$

这里的因果约束要求预测 $y_t$ 时看不到它自己及未来 token。训练时使用真实历史 $y_{<t}$，称为 teacher forcing；推理时使用已生成的历史，因此一个早期错误可能改变后续全部条件。训练 token loss 很低，仍可能在自由生成时出错，这是评估必须执行实际生成的原因之一。

设三个目标的条件概率为0.6、0.8、0.9，整段概率为0.432，总 NLL 为 $-\log(0.432)\approx0.8393$，平均 token NLL 约0.2798。我们使用自然对数，单位为 nats。序列越长，概率乘积通常越小；比较不同长度时必须说清使用总和还是均值。SFT 用什么归一化、DPO 用什么序列分数，是目标函数的一部分，不能随意替换。

[[LAB:chain]]

```python
import torch
p = torch.tensor([0.6, 0.8, 0.9])
sequence_logp = p.log().sum()
token_nll = -sequence_logp / p.numel()
assert torch.allclose(sequence_logp.exp(), p.prod())
```

实际模型不先乘所有概率再取 log，长序列会下溢；应从 `log_softmax(logits)` 提取目标 token 的 log 概率，再求和。模型对错误答案也能给出很高的概率，因此“概率大”表示模型偏好，不自动表示事实正确。

## 03 · 从训练阶段，转向学习信号

后训练把预训练得到的语言模型适配到明确的交互、任务和评估要求。预训练主要通过大规模序列预测建立通用表征；后训练改变模型在特定输入下生成什么、如何遵守约束，以及哪些行为更值得产生。工程边界取决于数据、目标和评估协议，不能用一条固定算力比例来定义。

一个常见开发流程是：**预训练 → 指令/任务适配 → 偏好或奖励优化 → 评估与迭代 → 部署**。它是可选、可回退的流程，而非每个模型都必须逐项完成的配方。领域继续预训练、蒸馏与安全训练也可能插入其中。推理时增加采样或检索不会直接更新权重，应和训练方案分开比较。[课程脉络：Stanford CS336](https://cs336.stanford.edu/spring2025/)

本课程实验选择已经过指令微调的 **Qwen2.5-0.5B-Instruct**，学习对已有助手做领域任务 SFT；不把它描述为从原始基座首次训练出助手。选择小模型是为了降低调试成本，不代表其效果足以满足生产要求。[模型卡](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct)

## 04 · 方法体系：目标、数据、可训练参数是三个维度

| 方法 | 学习信号 | 训练中发生什么 | 主要检查点 |
|---|---|---|---|
| SFT | 输入与目标输出 | 最大化示范输出的条件概率 | 示范质量、覆盖、标签掩码 |
| DPO | 同一输入的 chosen / rejected | 相对参考策略调整偏好对的概率比 | 偏好一致性、长度偏差、参考模型 |
| 奖励模型 + RLHF | 人类比较，随后学习奖励 | 拟合奖励模型，再优化策略的采样回答 | 奖励泛化、KL 约束、奖励投机 |
| RLVR | 可执行的结果验证 | 用验证器奖励优化模型采样 | 验证覆盖、漏洞、难题稀疏奖励 |

**LoRA / QLoRA 是参数化和资源策略，不是新的监督信号。** SFT 可以全参数更新，也可以只更新 LoRA；偏好优化同样可以与 PEFT 组合。这两个轴不能画成互相排斥的单选路线。

SFT 的目标可以写成：

$$\mathcal L_{\mathrm{SFT}}=-\frac{1}{N}\sum_{i,t}m_{i,t}\log\pi_\theta(y_{i,t}\mid x_i,y_{i,<t}),\quad N=\sum_{i,t}m_{i,t}.$$

$m$ 控制哪些 token 贡献损失。本课程只监督 assistant continuation；prompt 仍然参与前向计算，为回答提供条件。

DPO 的一个标准形式是：

$$\mathcal L_{\mathrm{DPO}}=-\mathbb E\log\sigma\!\left(\beta\left[\log\frac{\pi_\theta(y_w|x)}{\pi_{\rm ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_{\rm ref}(y_l|x)}\right]\right).$$

这解释了为什么偏好对和参考概率重要：优化的是相对偏好，而不是把 rejected 当成普通错误标签。该公式不要求在训练中另外拟合一个显式奖励模型；也不能据此推断 DPO 对所有任务优于在线 RL。[DPO 原论文](https://arxiv.org/abs/2305.18290)

## 05 · 从最大似然理解 SFT：示范数据定义了目标行为

给定示范集合 $D=\{(x_i,y_i)\}$，最大似然估计选择使示范最可能出现的参数。把乘积取对数、再取负号，就得到上一节的 token NLL。对一个输入只有一个示范，并不表示其它回答都错；它表示本次训练只拿这一个回答提供正向监督。数据覆盖、风格和标注政策因此会进入模型行为。

预训练和 SFT 可以采用同一类 next-token loss，但数据分布、格式以及监督位置不同。继续预训练通常针对领域语料的语言分布；SFT 针对“输入任务 → 期望响应”的条件行为。两者不是靠某一固定训练步数或数据量区分。蒸馏则描述知识来源：教师可以生成目标文本供学生做 SFT，也可以提供软分布；本课程只实施有明确目标文本的 SFT。

工单里写“我已经无法登录”与“攻击者进入了我的账户”，都可能属于 account，但后者是 urgent。若训练数据没有覆盖该区别，增加 rank 或训练步数不会替你补全标注政策。首先应修正信号，而不是立刻更换优化算法。

## 06 · 偏好学习：从 Bradley–Terry 到 DPO

只有“回答 A 比 B 更好”的信息时，不能直接把它当成标准答案 token。先假设每个回答有隐含效用 $r(x,y)$，用 Bradley–Terry 模型表达比较概率：

$$P(y_w\succ y_l\mid x)=\frac{e^{r_w}}{e^{r_w}+e^{r_l}}=\sigma(r_w-r_l),\quad L_{RM}=-\log\sigma(r_w-r_l).$$

若 $r_w-r_l=0$，偏好概率为0.5，loss为0.6931；若差值为2，概率约0.8808，loss约0.1269。对差值 $d$ 求导，得到 $\partial L/\partial d=\sigma(d)-1$。梯度下降会增大 chosen 相对 rejected 的分数差。给两个奖励都加同一个常数不改变比较结果，因此仅有偏好数据不能识别绝对奖励的零点。

DPO 的关键不是“删除奖励”这句口号，而是重参数化。对固定输入，考虑奖励与参考偏移之间的权衡：

$$\max_\pi\;\mathbb E_{y\sim\pi}[r(x,y)]-\beta D_{KL}(\pi\Vert\pi_{ref}).$$

在理想化分布优化中，引入概率和为1的约束，驻点满足 $\pi^*(y|x)\propto\pi_{ref}(y|x)e^{r(x,y)/\beta}$。移项得到 $r=\beta\log(\pi^*/\pi_{ref})+\beta\log Z(x)$。把同一输入下的两个奖励相减，未知的 $\log Z(x)$ 抵消。代入 BT 损失，便得到上面的 DPO 公式。这一步依赖偏好模型与优化假设，不是对任意人类偏好的无条件等价证明。

令 $m_\theta=\log\pi_\theta(y_w|x)-\log\pi_\theta(y_l|x)$，$m_{ref}$ 同理，$z=\beta(m_\theta-m_{ref})$，则 $L=\operatorname{softplus}(-z)$，$\partial L/\partial m_\theta=\beta(\sigma(z)-1)$。例如当前 log 概率为−4、−6，参考为−5、−6，β=0.5：校正后 margin 为1，z=0.5，loss约0.4741。**chosen 的绝对概率是否上升并非单独的保证**，网络参数共享会同时改变其它输出；目标约束的是相对关系。[推导与假设：DPO 论文第3–4节](https://arxiv.org/html/2305.18290v3)

[[LAB:preference]]

```python
import torch.nn.functional as F
# 每个 logp 都由回答 span 的 log_softmax 值求和；ref 不反传
margin = (chosen_logp - rejected_logp) - (ref_chosen - ref_rejected)
loss = F.softplus(-beta * margin).mean()
```

审计这段代码要问：两条回答是否共享同一 prompt？是否排除 prompt/padding？参考模型是否冻结？log 概率的求和契约是否一致？若把序列总和改成长度均值，就改变了标准 DPO 目标，应视为另一个实验设计。

## 07 · 在线奖励优化：策略梯度、PPO 与 RLVR 的边界

SFT 和离线 DPO 在固定数据上训练；在线方法从当前策略采样，再获得奖励。生成 token 是离散采样，不能对 token id 直接求普通导数。对期望奖励使用 score-function 恒等式：

$$\nabla_\theta\mathbb E_{y\sim\pi_\theta}[R(y)]=\mathbb E[R(y)\nabla_\theta\log\pi_\theta(y)].$$

减去不依赖所采样动作的基线可以降低方差，得到优势形式。直觉是：高于基线的回答应更容易再次出现，低于基线的回答应更少出现。奖励模型提供的是一个可被利用的代理目标；如果它只偏爱长回答，策略可能学会冗长而非有用。

PPO 使用采样时的旧策略 $\pi_{old}$ 构造概率比 $\rho_t=\pi_\theta(a_t|s_t)/\pi_{old}(a_t|s_t)$，最大化裁剪 surrogate：

$$J_{clip}=\mathbb E\min\{\rho_t A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\}.$$

当 A=1、ε=0.2、ρ=1.5，未裁剪项1.5被限制为1.2；当 A=−1、ρ=0.5，最终取−0.8，而非−0.5。裁剪并不是无条件把所有更新幅度截断，也不保证实际 KL 严格受限。旧策略用于采样比率，参考策略用于约束偏移，必须区分。完整 PPO 还包括优势估计、价值网络等组件，课堂动画只隔离这一局部目标。[PPO 原论文](https://arxiv.org/abs/1707.06347)

RLVR 描述奖励来自可验证结果，例如程序测试是否通过，并不是一个与 PPO 同层级的唯一优化器名字。组相对方法可对同一输入的多个回答计算 $A_i=(r_i-\bar r)/(\operatorname{std}(r)+\varepsilon)$。奖励为[0,0,1,1]时，采用总体标准差得到优势[−1,−1,1,1]；全0或全1时，组内信号为0。组标准化让难度、组大小和奖励稀疏性都影响学习；它也不等于具有独立基线的无偏 REINFORCE 估计。[组相对优化背景：DeepSeekMath](https://arxiv.org/abs/2402.03300)

[[LAB:policy]]

```python
rewards = torch.tensor([0., 0., 1., 1.])
adv = (rewards - rewards.mean()) / (rewards.std(unbiased=False) + 1e-8)
ratio = (new_logp - old_logp).exp()  # 同一已采样 token 的概率比
surrogate = torch.minimum(ratio * adv, ratio.clamp(.8, 1.2) * adv)
policy_loss = -surrogate.mean()  # 最大化 surrogate → 最小化负数
```

这段只实现局部示例，没有包含完整 rollout、reference KL 或 PPO critic，不能直接当作训练器。TicketLab 的验收项目实现 SFT；偏好和在线优化是用于选型与阅读论文的理论节点。若没有可靠偏好或验证器，给管线加 RL 名字不会自动带来更好的信号。
